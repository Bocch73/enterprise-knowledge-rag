# RAG quality evaluation assets

This directory contains reviewable evidence for retrieval and answer quality. It deliberately
keeps the corpus, labels, and reports outside application code so domain experts can review them
without reading Python.

## Directory layout

- `fixtures/`: small synthetic policy documents uploaded by the reference experiment.
- `datasets/`: versioned questions, relevant source labels, expected facts, and thresholds.
- `reports/`: machine-readable experiment results generated by the real application pipeline.

The current reports separate three different claims:

- `reference-retrieval-v1.json`: real ingestion and retrieval, with no model call.
- `reference-deterministic-full-v1.json`: real pipeline with stable local test answers.
- `reference-deepseek-v1.json`: five authorized calls to `deepseek-v4-flash` using only the synthetic fixtures.

The checked-in fixtures are fictional and contain no company or personal information. Never add
production documents to this directory. Use an approved private dataset location for real company
evaluation.

## Free reference experiment

From the project root:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run-reference-evaluation.ps1
```

This uses only the disposable database whose name ends in `_test`. It exercises migration,
authentication, upload, parsing, chunking, indexing, and hybrid retrieval without calling an
external model.

## Deterministic full-pipeline experiment

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run-reference-evaluation.ps1 `
  -Mode full `
  -GenerationProvider deterministic
```

The answer generator is fixed local test data. This proves that answer metrics and the quality
gate work; it does not claim to measure DeepSeek's language quality.

## Evaluation against a running knowledge base

Set credentials only in the current terminal or a local ignored environment file:

```powershell
$env:RAG_EVALUATION_EMAIL = "your-account@example.com"
$env:RAG_EVALUATION_PASSWORD = "your-password"
$env:RAG_EVALUATION_KNOWLEDGE_BASE_ID = "your-knowledge-base-uuid"

cd .\backend
.\.venv\Scripts\python.exe -m app.cli.evaluate_rag `
  --mode full `
  --output ..\evaluation\reports\my-private-baseline.json
```

The target knowledge base must contain the exact fixture filenames referenced by the selected
dataset. Do not commit reports that contain private questions, answers, or source names.
