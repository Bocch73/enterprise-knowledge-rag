# 非功能需求

## 1. 定义

非功能需求描述系统“以什么质量运行”，包括安全、性能、可靠性、可维护性和可观察性。编号格式为 `NFR-质量领域-编号`，其中 `NFR` 表示 Non-Functional Requirement（非功能需求）。

本文件中的性能数字是第一版待验证目标，不是已经取得的成绩，也不能写入简历作为实测结果。

## 2. 安全与隐私

| 编号 | 目标 | 验证方式 |
|---|---|---|
| NFR-SEC-001 | 所有业务接口默认需要认证，只有明确列入白名单的接口可以匿名访问。 | 路由安全测试。 |
| NFR-SEC-002 | 密码使用适合密码的单向哈希算法并带随机盐值，不记录明文密码。 | 代码审查和数据库检查。 |
| NFR-SEC-003 | 服务端对知识库和文档执行最小权限检查，禁止水平越权和垂直越权。 | 使用多用户、多角色的权限矩阵测试。 |
| NFR-SEC-004 | 密钥通过环境变量或密钥管理系统注入，日志、错误响应和版本库不得包含密钥。 | 密钥扫描和错误场景测试。 |
| NFR-SEC-005 | 上传默认不超过 20 MB，并防御伪造扩展名、路径穿越和压缩炸弹。 | 恶意样本测试。 |
| NFR-SEC-006 | 所有外部输入都有长度、类型、格式和允许值限制。 | 模糊测试与边界值测试。 |
| NFR-SEC-007 | 模型只接收当前用户有权访问的最小必要内容。 | 检索权限与模型调用替身断言。 |
| NFR-SEC-008 | 生产传输使用 HTTPS；会话凭证设置合理过期时间并支持失效。 | 部署配置检查和认证测试。 |

**水平越权**是普通用户读取另一个同级用户的数据；**垂直越权**是低权限用户执行管理员操作。

## 3. 性能目标

**第 95 百分位延迟**表示 95% 的请求在该时间以内完成，常写作 P95。它比只看平均值更能暴露少量很慢的请求。

第一版基准环境定义为：单机开发环境、10 个并发用户、10,000 个可检索片段、预热完成、不包含外部模型供应商自身耗时。

| 编号 | 第一版目标 | 验证方式 |
|---|---|---|
| NFR-PERF-001 | 普通知识库元数据接口 P95 不超过 500 毫秒。 | 固定负载测试脚本。 |
| NFR-PERF-002 | 混合检索 P95 不超过 1.5 秒。 | 固定问题集和并发负载。 |
| NFR-PERF-003 | 20 MB 以内文件的上传接口在 1 秒内返回任务编号，解析在后台继续。 | 上传计时测试。 |
| NFR-PERF-004 | 流式问答在 1 秒内返回“请求已接受”事件；模型首字时间单独记录。 | 事件流测试。 |
| NFR-PERF-005 | 每次问答分别记录检索、重排、模型和端到端耗时。 | 审计记录断言。 |

这些目标属于服务级别目标，不是对外合同。**服务级别目标**（Service Level Objective）是团队内部希望达到的可测量可靠性或性能目标，常简称 SLO。

## 4. 可靠性与数据一致性

| 编号 | 目标 | 验证方式 |
|---|---|---|
| NFR-REL-001 | 摄取任务允许重复投递，但同一个文档版本不会产生重复有效索引。 | 重复任务集成测试。 |
| NFR-REL-002 | 暂时性外部失败采用有限次数和指数退避重试。 | 故障注入测试。 |
| NFR-REL-003 | 数据库成功提交后才对外返回成功；失败事务不留下半成品业务状态。 | 事务回滚测试。 |
| NFR-REL-004 | Redis 不可用时，核心读取可回退数据库；后台任务不可投递时返回可追踪失败。 | 关闭依赖后的故障测试。 |
| NFR-REL-005 | 文档原文件、版本、片段和索引状态之间可以核对，不允许静默丢失。 | 数据一致性巡检。 |

**指数退避**是每次重试前等待更长时间，避免故障期间不断高频请求压垮依赖服务。

## 5. 可用性与恢复

| 编号 | 目标 | 验证方式 |
|---|---|---|
| NFR-AVL-001 | 第一版服务级别目标为月度可用性 99.5%，计划停机单独记录。 | 监控数据月度汇总。 |
| NFR-AVL-002 | 开发演示环境的恢复点目标为 24 小时。 | 备份策略和恢复演练。 |
| NFR-AVL-003 | 开发演示环境的恢复时间目标为 4 小时。 | 从备份恢复计时演练。 |

**恢复点目标**（Recovery Point Objective）表示最多可以接受丢失多长时间的数据，常简称 RPO。**恢复时间目标**（Recovery Time Objective）表示故障后希望在多长时间内恢复服务，常简称 RTO。

## 6. 可观测性

| 编号 | 目标 | 验证方式 |
|---|---|---|
| NFR-OBS-001 | 日志采用结构化字段，并包含时间、级别、服务、请求编号、事件和结果。 | 日志格式测试。 |
| NFR-OBS-002 | 指标至少覆盖请求量、错误量、延迟、任务积压、检索耗时和模型调用。 | 指标端点检查。 |
| NFR-OBS-003 | 一次问答可以通过关联编号贯穿接口、后台任务和模型调用。 | 端到端追踪检查。 |
| NFR-OBS-004 | 日志自动隐藏密码、令牌、模型密钥和完整敏感文档内容。 | 敏感字段测试。 |

## 7. 可维护性与测试

| 编号 | 目标 | 验证方式 |
|---|---|---|
| NFR-MNT-001 | 业务模块只能通过明确接口协作，不能任意跨模块直接修改数据。 | 架构测试和代码审查。 |
| NFR-MNT-002 | 公共函数和服务使用类型标注；静态类型检查无错误。 | mypy 检查。 |
| NFR-MNT-003 | 格式、代码规则和常见错误检查自动执行。 | Ruff 和前端检查。 |
| NFR-MNT-004 | 核心权限、摄取、检索和引用逻辑必须有单元与集成测试。 | 测试报告。 |
| NFR-MNT-005 | 总体分支覆盖率目标不低于 80%，安全关键模块目标不低于 90%。 | 覆盖率报告；同时人工审查测试质量。 |
| NFR-MNT-006 | 数据库结构只通过版本化迁移修改。 | 空数据库和旧版本升级测试。 |

测试覆盖率只说明哪些代码路径被执行过，不等于测试断言正确，因此不能单独作为质量证明。

## 8. 兼容性与部署

| 编号 | 目标 | 验证方式 |
|---|---|---|
| NFR-DEP-001 | Windows 支持早期本地开发；正式运行环境采用 Linux 容器。 | Windows 开发指南和容器集成测试。 |
| NFR-DEP-002 | Celery 工作进程不承诺在 Windows 原生运行，只在官方支持的 Linux 环境运行。 | 部署平台检查。 |
| NFR-DEP-003 | 配置与代码分离，相同构建产物可用于测试和生产配置。 | 多环境启动测试。 |
| NFR-DEP-004 | 新电脑按照文档可以完成安装、迁移和启动。 | 干净环境演练。 |
