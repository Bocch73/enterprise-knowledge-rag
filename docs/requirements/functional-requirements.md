# 功能需求

## 1. 如何阅读本文件

功能需求描述“系统必须提供什么行为”。每条需求都有稳定编号，格式为 `FR-模块-编号`：`FR` 是 Functional Requirement（功能需求）的标识。以后代码、测试和评测报告会引用这些编号，形成从需求到验证证据的追踪链。

优先级分为：

- **P0**：第一版必须完成，否则核心业务流程不成立。
- **P1**：第一版应该完成，缺失时仍能运行，但企业使用价值明显降低。
- **P2**：后续增强，不阻塞第一版交付。

## 2. 身份认证与账号

| 编号 | 优先级 | 需求 | 验收条件 |
|---|---|---|---|
| FR-AUTH-001 | P0 | 用户可以使用唯一用户名和密码注册。 | 合法信息创建账号；重复用户名返回明确冲突错误；密码不以明文保存。 |
| FR-AUTH-002 | P0 | 用户可以登录并获得有时效的访问凭证。 | 正确密码登录成功；错误密码只返回统一认证失败；凭证过期后受保护接口拒绝访问。 |
| FR-AUTH-003 | P0 | 已登录用户可以查看自己的基本信息并安全退出。 | 查询结果不包含密码哈希；退出后本地凭证被清除。 |
| FR-AUTH-004 | P1 | 系统管理员可以停用账号。 | 被停用账号不能登录，已有凭证也不能继续访问业务数据。 |

## 3. 知识库与成员权限

| 编号 | 优先级 | 需求 | 验收条件 |
|---|---|---|---|
| FR-KB-001 | P0 | 用户可以创建知识库并自动成为所有者。 | 创建成功后只有有权成员能看到知识库。 |
| FR-KB-002 | P0 | 有权限的用户可以查看、修改和删除知识库。 | 所有者可修改和删除；查看者不可修改；删除需要明确确认。 |
| FR-KB-003 | P0 | 所有者可以添加成员并分配所有者、编辑者或查看者角色。 | 每个接口都执行服务端权限检查，不能只依赖页面隐藏按钮。 |
| FR-KB-004 | P0 | 所有者可以修改成员角色或移除成员。 | 不能移除知识库最后一个所有者；权限变更立即影响后续请求。 |
| FR-KB-005 | P1 | 文档可以设置为知识库内可见或仅明确授权成员可见。 | 检索前完成文档级权限过滤，未授权片段不能进入模型上下文。 |

## 4. 文档与摄取

“摄取”是把外部文档转换成系统可检索数据的完整流程，包括校验、保存、解析、分块、生成向量和建立索引。

| 编号 | 优先级 | 需求 | 验收条件 |
|---|---|---|---|
| FR-DOC-001 | P0 | 编辑者可以上传 PDF、DOCX 和 Markdown 文档，默认上限为 20 MB。 | 系统同时检查扩展名、内容类型、文件结构和大小；不支持的文件返回明确错误。 |
| FR-DOC-002 | P0 | 系统为每次上传保存不可变文档版本和 SHA-256 文件指纹。 | 同一文档更新后旧版本仍可追溯；原文件不会被新版本静默覆盖。 |
| FR-DOC-003 | P0 | 文档摄取以后台任务执行，并展示阶段、进度和结果。 | 上传快速返回任务编号；任务状态至少包括等待、运行、完成和失败。 |
| FR-DOC-004 | P0 | 暂时性失败可以有限重试，永久性格式错误不能无限重试。 | 每次尝试有记录；达到上限后保留错误代码、错误信息和原文件。 |
| FR-DOC-005 | P0 | 编辑者可以查看解析文本和分块预览。 | 每个片段显示文档版本、页码或字符区间、标题路径。 |
| FR-DOC-006 | P1 | 编辑者可以删除文档或重新建立索引。 | 删除同时清理其可检索片段；重建期间保留可观察任务状态。 |

## 5. 检索

| 编号 | 优先级 | 需求 | 验收条件 |
|---|---|---|---|
| FR-RET-001 | P0 | 用户可以在有权限的知识库内执行关键词检索。 | 精确编号、名称和制度词语能够被检索；返回来源和关键词分数。 |
| FR-RET-002 | P0 | 用户可以执行向量检索。 | 问题被转换为向量，并按语义相似度返回有权限的片段。 |
| FR-RET-003 | P0 | 系统可以融合关键词和向量两路结果。 | 返回融合前排名、分数、融合后排名和使用的参数。 |
| FR-RET-004 | P1 | 系统可以对候选片段进行可选重排。 | 关闭重排时链路仍可用；开启后保留重排模型、耗时和分数。 |
| FR-RET-005 | P0 | 用户可以设置返回数量和检索模式，但参数必须有安全上限。 | 非法模式和超大返回数量被拒绝，不能造成无限查询。 |
| FR-RET-006 | P0 | 权限过滤必须发生在结果返回和模型调用之前。 | 自动化测试证明未授权片段不会出现在候选、缓存或模型上下文中。 |

## 6. 带引用问答

| 编号 | 优先级 | 需求 | 验收条件 |
|---|---|---|---|
| FR-CHAT-001 | P0 | 用户可以基于指定知识库提问并获得流式回答。 | 页面逐步接收回答事件；连接中断不会保存伪造的完整成功状态。 |
| FR-CHAT-002 | P0 | 每个事实性答案必须包含可展开的来源引用。 | 引用能定位到文档版本和原文片段；引用文本使用生成时快照。 |
| FR-CHAT-003 | P0 | 没有足够证据时系统必须拒绝猜测。 | 低于证据阈值时返回明确拒答原因，不调用或不采信无依据生成结果。 |
| FR-CHAT-004 | P0 | 用户可以继续多轮会话。 | 后续问题可以使用有限的会话上下文；不同用户会话严格隔离。 |
| FR-CHAT-005 | P1 | 系统记录每次问答的模型、参数、令牌数量、耗时和失败信息。 | 管理者能够追溯一次回答使用了哪些证据和模型调用。 |
| FR-CHAT-006 | P1 | 模型、向量模型和重排模型可以通过统一接口替换。 | 自动化测试使用不联网、可重复的本地替身；业务代码不绑定单一供应商。 |

## 7. 评测与审计

| 编号 | 优先级 | 需求 | 验收条件 |
|---|---|---|---|
| FR-EVAL-001 | P0 | 系统支持版本化的文档集、问题集和标准答案或标准证据。 | 每次实验记录数据集版本和文件哈希。 |
| FR-EVAL-002 | P0 | 系统分别评测检索质量和回答质量。 | 保存逐题原始结果，不只保存汇总数字。 |
| FR-EVAL-003 | P0 | 系统可以比较不同分块和检索配置。 | 报告包含配置、指标、延迟、失败样本和结论边界。 |
| FR-AUDIT-001 | P1 | 关键管理操作产生不可由普通用户修改的审计记录。 | 登录、权限变更、上传、删除和重试至少记录操作者、时间、对象和结果。 |
| FR-AUDIT-002 | P1 | 管理员可以按用户、操作、对象和时间查询审计记录。 | 查询本身受管理员权限保护，日志不返回密钥或密码。 |

## 8. 管理和运行

| 编号 | 优先级 | 需求 | 验收条件 |
|---|---|---|---|
| FR-OPS-001 | P0 | 系统提供存活检查和就绪检查。 | 存活检查只判断进程；就绪检查验证数据库和必要依赖。 |
| FR-OPS-002 | P1 | 系统提供结构化日志、指标和请求关联编号。 | 可以用一个请求编号串联接口、检索、模型调用和后台任务日志。 |
| FR-OPS-003 | P1 | 管理员可以查看摄取队列和失败任务。 | 能识别积压、失败原因和重试次数。 |

## 9. 需求变更规则

新增或修改 P0 需求时必须同步更新项目章程、架构影响、验收场景和测试计划。删除需求不能只删文字，还要检查是否存在对应接口、数据库字段、页面和测试。
