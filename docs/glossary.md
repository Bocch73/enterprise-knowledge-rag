# 术语表

本文件会随着项目推进持续补充。首次接触时先理解用途，不要求背诵。

| 术语 | 完整解释 |
|---|---|
| 检索增强生成 | Retrieval-Augmented Generation。先从外部知识库检索相关证据，再让大语言模型依据证据回答。常简称 RAG。 |
| 大语言模型 | Large Language Model。通过大量文本训练、能够理解和生成自然语言的模型。常简称 LLM。 |
| 前端 | 运行在用户浏览器中的页面和交互代码，负责展示但不能成为最终权限边界。 |
| 后端 | 运行在服务器中的接口和业务代码，负责权限、数据库、检索与模型调用。 |
| 单页应用 | Single-Page Application。初次加载一个页面外壳，之后由前端路由切换视图，常简称 SPA。 |
| Vue 组件 | 可独立维护和复用的页面单元，通过属性接收数据、通过事件通知父组件。 |
| TypeScript | 在 JavaScript 基础上增加静态类型的语言，帮助构建前发现字段和参数错误。 |
| Composition API | Vue 用函数组织响应式状态、计算值、监听和生命周期逻辑的接口。 |
| 前端路由 | 根据浏览器地址决定显示哪个页面组件的机制。 |
| 路由守卫 | 页面导航前执行的检查，例如未登录时转到登录页；不能代替后端授权。 |
| Pinia | Vue 官方生态的状态管理库，本项目用它保存当前用户和标签页会话令牌。 |
| 会话存储 | 浏览器当前标签页使用的键值存储，标签页关闭后清除，但同源 JavaScript 仍可读取。 |
| Fetch API | 浏览器原生网络请求接口，本项目用它发送 JSON、文件和读取流。 |
| 开发代理 | 开发服务器代为把浏览器的 `/api` 请求转发到后端，使浏览器保持同源。 |
| 跨域资源共享 | Cross-Origin Resource Sharing。服务器声明哪些外部来源可以读取响应的浏览器机制，常简称 CORS。 |
| 热更新 | 开发服务器在代码变化后只替换受影响模块，减少手工刷新并尽量保留状态。 |
| 响应式布局 | 页面根据屏幕宽度改变排列和尺寸，使桌面与手机都可用。 |
| 可访问性 | 让键盘、屏幕阅读器、低视力和减少动画偏好的用户也能使用软件。 |
| Mock | 测试中模拟外部服务行为的对象，用于获得稳定、无费用和不污染数据的验证。 |
| 组件测试 | 在内存浏览器环境中挂载一个前端组件，验证输入、点击、状态和渲染。 |
| 端到端测试 | 从浏览器入口经过多个组件验证完整用户流程的测试，常简称 E2E。 |
| 聊天补全 | Chat Completions。把带角色的一组消息发送给模型，由模型生成助手消息的接口形式。 |
| Provider | 能力提供者接口。业务代码依赖统一能力契约，DeepSeek 或测试替身负责具体实现。 |
| 提示词 | Prompt。发送给模型的规则、问题和上下文。系统提示词保存高优先级规则，用户提示词携带当前输入。 |
| Grounding | 让回答建立在可检查证据上的约束方式，降低模型脱离知识库猜测的风险。 |
| 幻觉 | 模型生成听起来合理但缺少证据、事实错误或与来源冲突的内容。 |
| 提示词注入 | Prompt Injection。在用户输入或文档中隐藏恶意指令，试图让模型忽略原规则或泄露信息。 |
| 引用白名单 | 只允许模型使用本次实际提供的来源编号，范围外引用会被拒绝。 |
| 引用快照 | 回答生成时复制保存的来源文本和定位信息，用于文档变化后的历史审计。 |
| 词元 | Token。模型处理文字的计量单位，可能是汉字、词的一部分或标点，常用于容量与费用计算。 |
| 服务器发送事件 | Server-Sent Events。服务器通过持续的超文本传输协议连接按顺序推送文本事件，常简称 SSE。 |
| 冒烟测试 | Smoke Test。用很小的输入快速确认最关键链路可用的检查。 |
| 失败关闭 | 系统不能证明结果安全或有效时采用保守拒绝，而不是继续返回可疑结果。 |
| 向量表示 | Embedding。把文本转换为一组数字，使语义相近的文本在数学空间中距离更近。 |
| 向量数据库能力 | 保存向量并按相似度查找的能力。本项目通过 PostgreSQL 的 pgvector 扩展提供。 |
| 关键词检索 | 根据词语是否出现以及重要程度查找文本，适合精确名称、编号和专有词。 |
| 混合检索 | 同时使用向量检索和关键词检索，再融合两路结果。 |
| 全文检索 | 把文档和用户问题规范化为词项结构后进行匹配与相关性排序的检索方式，不只是简单字符串包含判断。 |
| tsvector | PostgreSQL 保存文档规范化搜索词项及位置的数据类型。 |
| tsquery | PostgreSQL 表达结构化全文搜索条件的数据类型。 |
| 广义倒排索引 | Generalized Inverted Index，保存词项到数据库行的映射，常简称 GIN；PostgreSQL 推荐它用于全文检索。 |
| 候选召回 | 从全部数据中先找出一批可能相关结果的阶段，目标是让正确证据进入后续融合或重排。 |
| 余弦距离 | 衡量两个向量方向差异的数值，距离越小通常表示方向越接近。 |
| 重排 | Reranking。对初步找出的候选结果进行第二次、更精细的相关性排序。 |
| 文本分块 | Chunking。把过长文档切成适合检索和传给模型的小片段。 |
| 重叠窗口 | 相邻文本片段共享的一段内容，用于降低完整事实恰好跨越切分边界而丢失的风险。 |
| 源文本位置 | 片段在解析全文中的起止字符编号，可用于验证内容、定位原文和生成引用。 |
| 向量维度 | 一个向量包含的数字数量，由向量模型决定。本项目当前数据库固定为 384 维。 |
| 精确向量检索 | 对满足条件的全部向量计算距离并排序，结果精确但计算量会随数据增长。 |
| 近似最近邻 | 用额外索引快速寻找大概率最相近结果的方法，速度更快但可能遗漏少量真实最近结果。 |
| 数据回填 | 系统升级后为历史记录补充新结构所需数据的过程，需要可重试、可观测并控制资源消耗。 |
| 召回率 | 应该找到的相关内容中，系统实际找到的比例。 |
| 精确率 | 系统找到的内容中，真正相关的比例。 |
| 应用程序编程接口 | Application Programming Interface。不同软件模块之间按约定交换数据的入口。常简称 API。 |
| 持续集成 | Continuous Integration。每次提交代码后自动执行测试和质量检查。常简称 CI。 |
| 容器 | 把应用及其运行依赖打包在隔离环境中的技术，使开发机和服务器运行方式更一致。 |
| 数据库迁移 | 用有版本的脚本逐步修改数据库结构，并能在不同环境重复执行。 |
| 模块化单体 | 一个可整体部署的后端应用，内部仍按业务领域划分清楚模块。 |
| 微服务 | 把系统拆成多个独立部署、通过网络通信的服务。它带来独立扩展能力，也显著增加部署和运维复杂度。 |
| 可观测性 | 通过日志、指标和请求追踪理解系统内部发生了什么，并快速定位故障。 |
| 幂等性 | 同一个操作执行一次或重复执行多次，最终结果保持一致的性质。 |
| 架构决策记录 | Architecture Decision Record。记录一个重要技术选择的背景、方案、决定和后果。常简称 ADR。 |
| 虚拟环境 | 为单个 Python 项目创建的隔离依赖空间，防止不同项目的库版本互相影响。 |
| 运行时 | 执行程序所依赖的软件环境，例如 Python 和 Node.js。 |
| 长期支持版 | Long-Term Support。在较长周期内持续获得稳定性和安全更新的软件版本，常简称 LTS。 |
| 工作区 | Git 中正在编辑、尚未正式提交的文件区域。 |
| 暂存区 | Git 中已经选择、准备放入下一次提交的改动区域。 |
| 提交 | Commit。保存到本地 Git 版本库的一次带作者、时间和说明的历史快照。 |
| 拉取请求 | Pull Request。请求审查并把一个分支合入另一个分支的变更单，常简称 PR。 |
| Squash merge | 把功能分支上的多个临时提交压缩成一个正式提交后再合入主分支。 |
| Conventional Commits | 一套结构化提交信息规范，用类型和说明表达每次提交的目的。 |
| 功能需求 | Functional Requirement。描述系统必须提供什么行为，例如上传文档或检索。 |
| 非功能需求 | Non-Functional Requirement。描述系统以什么质量运行，例如安全、性能和可靠性。 |
| 验收条件 | 能够判断一项需求是否完成的具体、可观察结果。 |
| 唯一可信来源 | Source of Truth。数据冲突时被视为最终正确的数据位置。 |
| 依赖倒置 | 核心业务依赖抽象接口，具体数据库和外部服务去实现接口的设计原则。 |
| OpenAPI | 描述 HTTP 接口路径、参数、响应和认证方式的开放规范。 |
| 对象关系映射 | Object-Relational Mapping。把程序对象与关系数据库表关联的技术，常简称 ORM。 |
| 第 95 百分位延迟 | 95% 请求都能在该时间以内完成的延迟指标，常写作 P95。 |
| 服务级别目标 | Service Level Objective。团队内部希望达到的可测量性能或可靠性目标，常简称 SLO。 |
| 恢复点目标 | Recovery Point Objective。故障时最多可以接受丢失多长时间的数据，常简称 RPO。 |
| 恢复时间目标 | Recovery Time Objective。发生故障后希望在多长时间内恢复服务，常简称 RTO。 |
| 水平越权 | 用户访问另一个同级用户数据的未授权行为。 |
| 垂直越权 | 低权限用户执行管理员等高权限操作的未授权行为。 |
| 指数退避 | 每次重试前逐步增加等待时间，避免故障期间持续高频请求。 |
| 倒数排名融合 | Reciprocal Rank Fusion。根据候选在多个结果列表中的名次计算统一分数，常简称 RRF。 |
| HNSW | Hierarchical Navigable Small World，分层可导航小世界图，用于近似向量搜索的多层图索引。 |
| Provider | 对某种外部能力的抽象提供者接口，例如生成、向量或重排接口。 |
| Broker | 在任务发送者和工作进程之间保存并转发消息的消息代理。 |
| 反向代理 | 位于客户端与应用服务之间，负责加密连接、转发请求和入口策略的服务器。 |
| 持久卷 | 容器删除或重建后仍保留数据的存储空间。 |
| FastAPI | 一个用于构建 Python 网络接口的框架，能够根据类型声明校验数据并生成 OpenAPI 接口说明。 |
| Uvicorn | 负责接收网络请求并运行 Python 异步应用的服务器程序。开发时由它启动 FastAPI 应用。 |
| 异步服务器网关接口 | Asynchronous Server Gateway Interface。Python 异步网络服务器与应用之间的通信约定，常简称 ASGI。 |
| 应用工厂 | 用一个函数创建并配置应用实例的模式。测试可以用不同配置创建隔离实例，避免依赖全局状态。 |
| 中间件 | 位于请求进入业务处理之前和响应返回之后的公共处理层，适合统一加入请求编号、日志和安全响应头。 |
| 请求编号 | Request ID。每个请求的唯一标识，可同时出现在响应与日志中，用于串联一次请求的全部记录。 |
| 上下文变量 | Context Variable。在并发任务之间隔离保存上下文数据的机制，本项目用它让每条日志取得当前请求编号。 |
| 结构化日志 | 按固定字段输出的日志，例如 JSON 对象。日志平台可以直接按请求编号、状态码或耗时查询和统计。 |
| 存活检查 | Liveness Check。判断应用进程是否仍能响应；失败通常意味着进程需要重启。 |
| 就绪检查 | Readiness Check。判断应用及其必要依赖是否可以接收业务流量；失败时应暂时停止转发新请求。 |
| 环境变量 | 由操作系统或启动环境提供的名称和值，可在不修改代码的情况下配置环境、日志级别和服务地址。 |
| 数据模型校验 | 按字段类型和规则检查输入或配置是否合法，错误数据在进入业务逻辑前就会被拒绝。 |
| 依赖锁文件 | 固定直接依赖及其间接依赖准确版本的文件，用于降低不同机器安装结果不一致的风险。 |
| 直接依赖 | 项目代码明确选择并直接使用的软件包，例如 FastAPI。 |
| 间接依赖 | 由直接依赖继续依赖的软件包，例如 FastAPI 所依赖的 Starlette。 |
| 单元测试 | 针对一个较小代码单元进行快速、隔离验证的自动化测试。 |
| 测试覆盖率 | 测试执行时被运行到的代码比例。高覆盖率不等于没有缺陷，但能帮助发现未被验证的路径。 |
| 静态类型检查 | 不运行程序就检查参数、返回值和变量类型是否一致，提前发现一类类型错误。 |
| 代码规范检查 | 自动发现未使用导入、潜在错误、不安全写法和风格问题的静态检查。 |
| PostgreSQL 角色 | 数据库服务器内部的账户或权限主体。只有带登录属性的角色才能直接连接数据库；它和业务系统里的用户角色不是同一个概念。 |
| 最小权限原则 | 账户只拥有完成职责所必需的权限。本项目后端使用不能创建数据库、不能创建角色、不是超级管理员的专用账户。 |
| SQLAlchemy | Python 数据访问工具。本项目使用它的对象关系映射和异步会话管理 PostgreSQL 事务。 |
| Psycopg | Python 连接 PostgreSQL 的驱动。本项目使用第 3 代驱动及其异步模式。 |
| Alembic | SQLAlchemy 项目的数据库迁移工具，用有顺序的版本文件升级或回退数据库结构。 |
| 事务 | 一组要么全部成功、要么全部撤销的数据库操作，用于防止只完成一半的数据状态。 |
| 主键 | 一张表中唯一标识每一行的字段或字段组合。 |
| 外键 | 指向另一张表主键的约束，用于维护数据之间的引用完整性。 |
| 索引 | 数据库为加快查找而维护的数据结构。索引能提升读取速度，但会占用空间并增加写入成本。 |
| 通用唯一识别码 | Universally Unique Identifier。一个 128 位标识，本项目用它作为可公开资源编号，常简称 UUID。 |
| 级联删除 | 删除父记录时由数据库自动删除依赖记录，例如删除知识库时删除成员关系。 |
| 限制删除 | 存在被引用记录时拒绝删除父记录，例如知识库仍属于某用户时不允许直接删除该用户。 |
| 身份认证 | Authentication。确认请求者是谁，例如校验邮箱、密码和访问令牌。 |
| 权限授权 | Authorization。确认已经识别的请求者能做什么，例如查看者不能管理知识库成员。 |
| 密码哈希 | 使用单向、故意耗费计算资源的算法保存密码摘要，登录时比较摘要，而不是保存或还原明文密码。 |
| Argon2 | 专为密码存储设计的内存困难哈希算法；增加暴力猜测每次尝试的计算和内存成本。 |
| 盐值 | 每个密码哈希中加入的随机数据，使相同密码也产生不同结果，并抵抗预计算彩虹表。 |
| JSON 网络令牌 | JSON Web Token。一种带签名的紧凑令牌，常简称 JWT。内容可被读取但不可在不破坏签名的情况下篡改；它不是加密文件。 |
| Bearer 令牌 | 持有者即可使用的访问凭据，因此必须通过加密连接传输，并避免写入日志。 |
| 基于角色的访问控制 | Role-Based Access Control。把权限授予角色，再把角色授予用户，常简称 RBAC。 |
| 全局角色 | 对整个应用生效的角色，例如 `admin` 和 `member`。 |
| 资源角色 | 只对一个具体资源生效的权限，例如某个知识库中的 `owner`、`editor` 和 `viewer`。 |
| 复合主键 | 由多个字段共同组成的主键。本项目用知识库编号和用户编号唯一确定一条成员关系。 |
| 数据库结构漂移 | 代码中的模型定义与实际数据库表结构不一致。`alembic check` 用于在提交前发现这种差异。 |
| 文档摄取 | 把外部文件经过校验、保存、解析、分块、生成向量和建立索引，转换成系统可检索数据的完整流程。 |
| 媒体类型 | 网络协议中描述内容格式的标识，也称 MIME Type，例如 PDF 对应 `application/pdf`。它由客户端声明，服务端不能单独信任。 |
| 对象存储 | 使用唯一对象键保存和读取文件内容的存储方式。业务通常不依赖传统目录操作，可由本地文件系统或兼容 Amazon Simple Storage Service 的服务实现。 |
| 存储键 | 对象在对象存储中的唯一位置标识。本项目由服务器随机生成，不使用用户文件名构造。 |
| 不可变版本 | 创建后不再原地修改的历史版本。文档更新会创建新版本，旧版本继续保留以支持引用和审计。 |
| SHA-256 | Secure Hash Algorithm 256-bit，一种输出 256 位摘要的安全哈希算法。本项目用它生成文件内容指纹；它不是加密，也不是本项目的密码哈希算法。 |
| 文件指纹 | 根据完整文件内容计算出的稳定摘要，用于识别重复内容和核对完整性。 |
| 路径穿越 | 攻击者利用 `../`、绝对路径或路径分隔符让程序访问预期目录之外文件的漏洞。 |
| 压缩炸弹 | 压缩体积很小、展开后异常巨大的恶意归档，可能耗尽内存、磁盘或处理时间。DOCX 本质上是 ZIP 包，因此也需要展开限制。 |
| Office Open XML | Microsoft Office 2007 以后主要文档格式所使用的开放 XML 包格式，DOCX 文件本质上是包含多个 XML 文件的 ZIP 包。 |
| 状态机 | 明确定义对象允许的状态及状态转换规则的模型。本项目摄取任务包括等待、运行、完成和失败。 |
| 后台工作进程 | 独立于网络接口执行耗时任务的程序，使上传请求可以快速返回并让任务独立重试。 |
| 任务队列 | 保存等待执行任务并把任务交给工作进程的机制。当前本地实现用 PostgreSQL 持久任务表，正式架构计划使用 Redis 和 Celery。 |
| 行级锁 | 数据库对选中记录施加的并发控制。任务领取时锁住一行，避免两个工作进程同时取得它。 |
| SKIP LOCKED | PostgreSQL 锁定查询选项，表示跳过已被其他事务锁住的行，适合多个消费者并发访问队列式表。 |
| 暂时错误 | 等待后可能恢复的失败，例如存储短暂不可用，适合有限重试。 |
| 永久错误 | 不修改输入或配置就不会恢复的失败，例如损坏文档或不支持的加密文件，不应自动无限重试。 |
| 陈旧任务 | 已标记运行但超过约定时间没有更新的任务，通常表示工作进程崩溃或失联。 |
| 补偿操作 | 当跨系统流程后半部分失败时，用反向动作减小不一致，例如数据库写入失败后删除刚保存的对象。 |
| 光学字符识别 | Optical Character Recognition，从图片或扫描页面识别文字的技术，常简称 OCR。pypdf 只能提取已有文字层，不等同于光学字符识别。 |
| 评测集 | 一组经过人工审阅并固定版本的问题、正确来源和预期事实，用来公平比较不同系统版本。 |
| 基准线 | 第一次正式、可重复实验的结果，后续改动用它判断质量提升或退化。 |
| Top K | 只选择排序最靠前的 K 个结果。K 是一个正整数，例如 Top 3 表示前三个结果。 |
| 命中率 | 前 K 个检索结果中至少出现一个相关来源的问题比例。它只判断是否命中，不区分具体排名。 |
| 平均倒数排名 | Mean Reciprocal Rank。对第一个相关结果排名取倒数再求平均，常简称 MRR。 |
| 归一化折损累计增益 | Normalized Discounted Cumulative Gain。根据相关性和排名位置计算并归一化的检索排序指标，常简称 NDCG。 |
| 检索精确率 | 返回的检索结果中相关结果所占比例，用来观察结果噪声。 |
| 检索召回率 | 全部人工标注相关来源中被系统找回的比例，用来观察资料遗漏。 |
| 引用准确率 | 回答引用的来源中属于人工标注正确来源的比例。 |
| 引用召回率 | 人工标注的正确来源中被回答实际引用的比例。 |
| 关键事实覆盖率 | 回答命中人工指定事实或其替代表达的比例。它是可重复的字符串代理指标，不等同于完整语义正确率。 |
| 拒答准确率 | 系统在资料不足时拒答、资料充足时正常回答的行为与人工标签一致的比例。 |
| 质量门禁 | 把关键质量指标与最低门槛比较，不达标时让自动化流程失败的工程约束。 |
| 模型评委 | 使用另一个大语言模型判断回答相关性、忠实度或正确性的评测方法，需要控制费用、随机性和偏差。 |
| 数据指纹 | 对评测集或文档规范化内容计算的哈希值，用于证明不同实验是否使用完全相同的数据。 |
| 限流 | 限制一个客户端在一定时间内请求次数的资源保护措施。超过限制通常返回网络状态码 429。 |
| 固定时间窗口 | 把时间划分为固定区间并在每个区间独立计数的限流算法，实现简单但窗口交界处可能出现短时突发。 |
| 429 Too Many Requests | 表示客户端请求频率超过服务限制的网络状态码。 |
| Retry-After | 响应头，告诉客户端在多少秒后或哪个时间点之后再重试。 |
| 生存时间 | Time To Live。缓存项从写入到过期的时间，常简称 TTL。 |
| 最近最少使用淘汰 | Least Recently Used。容量满时优先删除最长时间未访问缓存项的策略，常简称 LRU。 |
| 缓存击穿 | 热门缓存项失效时大量并发请求同时访问后端计算或存储的现象，也称缓存惊群。 |
| Prometheus | 采集、保存和查询时间序列指标并支持告警的开源监控系统。 |
| 指标采集 | 监控系统定时访问应用指标端点并保存结果的过程，英文常称 scrape。 |
| 计数器 | Counter。只增加的指标类型，适合累计请求、错误和调用次数。 |
| 仪表 | Gauge。可以增加或减少的指标类型，适合表示当前任务积压等状态。 |
| 直方图 | Histogram。把观察值放入多个区间的指标类型，适合延迟分布和分位数计算。 |
| 高基数标签 | 标签可能产生大量不同值的指标设计，例如用户编号或请求编号，会造成大量时间序列和潜在信息泄露。 |
| 审计事件 | 用于安全追责的结构化持久记录，描述谁在何时对什么资源执行了什么操作以及结果。 |
| 追加式记录 | 应用只允许新增和读取、不提供更新或删除入口的数据模式；它不自动等于数据库级绝对不可篡改。 |
| 指标 Bearer 令牌 | 监控采集端访问指标接口使用的独立持有者凭据，不是业务用户的登录令牌。 |
| 多进程指标模式 | 多个工作进程通过官方约定汇总各自内存指标的运行方式，需要共享目录和进程生命周期清理。 |
| 持续交付 | Continuous Delivery。质量门禁通过后自动生成随时可部署制品，但生产上线仍保留人工批准。 |
| 持续部署 | Continuous Deployment。质量门禁通过后自动把变更上线生产，不保留人工批准。 |
| 工作流 | Workflow。自动化过程的完整定义，GitHub Actions 使用 YAML 文件描述。 |
| 任务 | Job。工作流中在一个执行器上完成的一组步骤，不同任务可以并行或设置依赖。 |
| 步骤 | Step。任务中的单个动作或命令，例如检出代码、安装依赖或运行测试。 |
| 执行器 | Runner。实际执行持续集成任务的机器，可以由 GitHub 托管或由组织自行管理。 |
| 服务容器 | 只在流水线任务期间提供数据库或缓存等依赖的临时容器，任务结束后销毁。 |
| 制品 | Artifact。构建或测试产生并保存的结果，例如覆盖率文件、评测报告和容器镜像。 |
| 容器镜像仓库 | Registry。保存、授权和分发容器镜像的服务。 |
| 镜像标签 | 便于人识别镜像版本的可变名称，例如 0.2.0；标签理论上可以重新指向其他内容。 |
| 镜像摘要 | Digest。根据镜像内容计算的不可变标识，用于精确证明部署内容和可靠回滚。 |
| 多阶段构建 | Dockerfile 使用多个阶段，把编译和安装环境与最终运行环境分开的构建方式。 |
| 软件物料清单 | Software Bill of Materials。列出制品包含的软件组件和版本，常简称 SBOM。 |
| 构建来源证明 | Provenance。描述制品来自哪个源代码修订和构建过程的供应链证据。 |
| 语义化版本 | 使用主版本、次版本和修订版本表达不兼容变化、新功能和修复的版本规则。 |
| 推广 | 把同一个已经验证的制品从测试环境逐步用于预发布和生产，而不是重新构建。 |
| 回滚 | 发布失败时恢复到上一个已验证应用版本或数据状态的过程。 |
| 扩展与收缩迁移 | 先添加兼容结构、再迁移读写、最后删除旧结构的数据库演进方式。 |
| Linux capability | 从 root 权限拆分出的细粒度系统能力，容器可以删除不需要的能力来缩小攻击面。 |
| 只读文件系统 | 运行时不允许修改容器主体文件，只为临时目录和持久数据卷保留明确写入位置。 |
| 电梯陈述 | 在很短时间内说明目标用户、问题、方案和结果的项目介绍。 |
| STAR 方法 | 按背景、任务、行动和结果组织经历的表达方法，英文分别为 Situation、Task、Action、Result。 |
| 技术权衡 | 选择方案时同时比较收益、代价、适用范围和演进条件，而不是声称某项技术绝对最好。 |
| 证据链 | 让需求、设计、代码、测试和结果可以互相对应并被复查的一组材料。 |
| 演示降级方案 | 外部服务或现场环境失败时切换到已验证备用路径的预案，必须明确哪些是历史结果。 |
| 项目边界 | 对已经实现、已经测试、只完成配置和尚未完成的能力作出的明确区分。 |
