# 第 11 步：建立可重复的 RAG 质量评测体系

## 1. 本步目标

前十步证明系统“能够运行”，本步开始回答更重要的问题：它“运行得有多好”。

本步交付四类证据：

1. **版本化评测集**：固定问题、人工确认的正确来源、答案关键事实和质量门槛。
2. **可解释指标**：每个分数都有明确公式，不依赖不可见的模型判断。
3. **可重复实验**：使用隔离测试数据库，自动走上传、解析、分块、索引、检索和回答链路。
4. **机器可读报告**：报告使用 JSON 格式，未来可以直接接入持续集成流水线。

## 2. 为什么普通自动化测试不够

普通测试常验证“接口返回 200”“字段存在”“无权限用户被拒绝”。这些是功能正确性，
却不能证明第一个检索结果是不是正确文档，也不能证明回答是否引用了正确来源。

RAG 是“检索”和“生成”串联的系统。最终回答错误时，至少可能有三种原因：

- 检索没有找到正确资料；
- 找到了资料，但排序太靠后，没有进入模型上下文；
- 模型看到了资料，但回答遗漏、误解或错误引用。

因此必须分别度量检索层和回答层，才能定位问题。

## 3. 新名词解释

### 3.1 评测集

评测集是一组经过人工审阅的固定测试样本。每个样本包含问题、是否可以回答、正确来源和
答案必须包含的关键事实。固定版本能保证两次实验比较的是同一批问题。

### 3.2 基准线

基准线是第一次正式实验得到的结果。以后更换分块大小、向量模型或排序方法时，要与基准线
比较，而不是凭感觉判断效果。

### 3.3 Top K

Top K 表示只查看排序最靠前的 K 个检索结果。本项目评测集使用 Top 3，即每题检查前三个结果。

### 3.4 命中率

命中率衡量“前 K 个结果中是否至少出现一个正确来源”。命中记为 1，未命中记为 0，最后对
所有可回答问题求平均。

### 3.5 平均倒数排名

平均倒数排名英文是 Mean Reciprocal Rank。正确来源排第 1 得 1 分，排第 2 得二分之一，排第
3 得三分之一，未出现得 0 分。它比命中率更关注正确结果是否足够靠前。

### 3.6 归一化折损累计增益

归一化折损累计增益英文是 Normalized Discounted Cumulative Gain。它对越靠后的正确结果给予
越小权重，再除以理想排序的分数，将结果归一化到 0 至 1。它适合评价一组有顺序的检索结果。

### 3.7 检索精确率与检索召回率

- 检索精确率：返回结果中有多少是相关的，反映噪声多少。
- 检索召回率：人工标注的相关来源中有多少被找回，反映遗漏多少。

扩大 Top K 往往提高召回率，却可能降低精确率并增加模型上下文噪声。

### 3.8 引用准确率与引用召回率

- 引用准确率：回答引用的来源中，有多少属于人工标注的正确来源。
- 引用召回率：人工标注的正确来源中，有多少实际被回答引用。

### 3.9 关键事实覆盖率

评测集把必须出现的事实写成同义词组。例如 `15` 和 `十五` 是同一事实的两种表达。程序检查
每组是否至少命中一种表达。这个指标便宜、稳定、容易解释，但它不能理解复杂语义，也不能
单独证明整段回答事实正确。

### 3.10 拒答准确率

知识库没有依据时应该拒绝回答；有依据时不应错误拒答。拒答准确率衡量这两种行为是否符合
人工标签。

### 3.11 质量门禁

质量门禁是一组最低分数要求。任何关键指标低于门槛，命令就返回失败状态，未来持续集成流水线
可以据此阻止有明显质量退化的版本进入主分支。

## 4. 评测架构

```text
版本化评测集
    │
    ├── 问题 + 正确来源 ──> 真实搜索接口 ──> 排名指标
    │
    └── 是否可回答 + 关键事实 ──> 真实回答接口 ──> 引用、事实与拒答指标
                                                   │
                                                   v
                                      JSON 实验报告 + 质量门禁
```

评测器使用公开 HTTP 接口，因此它属于“黑盒评测”：只观察系统输入输出，不读取检索函数内部
变量。这更接近真实用户，也允许未来用同一套工具评测测试环境或生产前环境。

## 5. 项目文件

- `evaluation/fixtures/`：三份虚构的中英文公司制度文档。
- `evaluation/datasets/company-policy-v1.json`：五个经过人工标注的问题。
- `evaluation/reports/`：实际运行生成的实验报告。
- `backend/app/modules/evaluation/metrics.py`：透明的指标公式。
- `backend/app/modules/evaluation/runner.py`：逐题执行并聚合报告。
- `backend/app/modules/evaluation/client.py`：调用运行中后端的安全客户端。
- `backend/app/cli/evaluate_rag.py`：评测任意已运行知识库。
- `backend/app/cli/run_reference_evaluation.py`：构建隔离语料并运行参考实验。

## 6. 读懂评测集

一个可回答样本的简化结构如下：

```json
{
  "id": "leave-entitlement",
  "question": "全职员工每年有多少天带薪年假？",
  "answerable": true,
  "relevant_sources": ["leave-policy.md"],
  "required_answer_terms": [["15", "十五"], ["年假", "annual leave"]]
}
```

`required_answer_terms` 外层列表表示所有必须覆盖的事实组；每个内层列表表示可以接受的替代表达。
不可回答样本不能填写正确来源或关键事实，严格校验会阻止矛盾标签进入实验。

## 7. 第一次运行：验证评测代码

在项目根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\verify-evaluation.ps1
```

它会完成：评测集结构校验、14 个评测单元测试、代码风格检查和严格类型检查。这一步不调用
DeepSeek。

## 8. 第二次运行：真实检索参考实验

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run-reference-evaluation.ps1
```

该命令只允许数据库名称以 `_test` 结尾，然后自动完成数据库迁移、临时用户、知识库、上传、
文档工作进程和真实混合检索。对象文件使用临时目录，实验结束后自动清理。

| Top 3 命中率 | 1.000 | 四个可回答问题都找到了正确来源 |

| 检索召回率 | 1.000 | 所有人工标注的相关来源都被找回 |

## 9. 第三次运行：不联网的完整链路实验

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run-reference-evaluation.ps1 `
  -Mode full `
  -GenerationProvider deterministic
```

这次真实执行回答接口、引用校验和审计写入，但生成器使用固定本地答案，所以结果可以重复，
也不会把文本发送给第三方。实际引用准确率、引用召回率、关键事实覆盖率、拒答准确率和有依据
回答率均为 1.000。

这个结果只证明“评测器和回答链路正确”，不能用来宣称 DeepSeek 的回答质量达到 100%。报告
位于 `evaluation/reports/reference-deterministic-full-v1.json`。

## 10. 真实 DeepSeek 评测

本次在用户明确确认三份虚构评测资料可以发送给 DeepSeek，并接受少量接口费用后运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run-reference-evaluation.ps1 `
  -Mode full `
  -GenerationProvider configured `
  -Output .\evaluation\reports\reference-deepseek-v1.json `
  -AllowThresholdFailure
```

`AllowThresholdFailure` 只允许首轮基准线即使未达门槛也生成报告，不会把失败改成成功。调优完成后
应删除该选项，让质量退化产生非零退出状态。

## 11. 评测已有知识库

确保后端已启动，并在当前终端设置本地环境变量：

```powershell
$env:RAG_EVALUATION_EMAIL = "你的登录邮箱"
$env:RAG_EVALUATION_PASSWORD = "你的登录密码"
$env:RAG_EVALUATION_KNOWLEDGE_BASE_ID = "知识库标识符"

cd .\backend
.\.venv\Scripts\python.exe -m app.cli.evaluate_rag `
  --mode full `
  --output ..\evaluation\reports\private-baseline.json
```

密码和访问令牌不会写入报告。真实企业数据的评测集与报告可能包含敏感问题、答案和文件名，
应保存在经过授权的私有位置，不应直接提交到公开仓库。

## 12. 怎样分析失败

- 命中率低：检查分块、向量表示、查询语言和候选数量。
- 命中率高但平均倒数排名低：正确文档存在，但融合或重排需要优化。
- 检索好但引用召回率低：提示词或模型没有充分使用证据。
- 关键事实覆盖率低：可能是资料没进入上下文，也可能是生成时遗漏。
- 拒答准确率低：需要加强证据阈值、拒答提示词或回答后校验。
- 精确率低但召回率高：返回结果过多或噪声较大，需要调整 Top K 或增加重排。

## 13. 本次评测的边界

1. 只有五个虚构样本，适合验证工程闭环，不足以代表真实企业业务。
2. 当前本地向量提供器是确定性哈希实现，不是真实语义嵌入模型。
3. 来源以文件名标注，尚未细化到每个文本片段的相关性等级。
4. 关键事实覆盖率是字符串代理指标，不等同于完整的语义忠实度。
5. 本机毫秒级响应时间不能外推为并发环境的容量结果。
6. 本次 DeepSeek 实验只获得了三份虚构样本文档的发送授权；真实企业资料仍需重新完成数据分级、脱敏和外发审批。

企业下一阶段应由领域专家扩充到至少数十个真实且脱敏的问题，并定期抽样人工复核自动指标。

## 16. 本步知识点总结

1. RAG 评测必须把检索问题与生成问题分开定位。
2. 评测集必须版本化、人工审阅并包含不可回答问题。
3. 命中率看“找没找到”，平均倒数排名和归一化折损累计增益看“排得好不好”。
4. 召回率与精确率需要一起看，不能只追求其中一个。
5. 自动代理指标必须明确局限，不能把关键字命中包装成完整事实性证明。
6. 质量门禁把实验结果变成工程约束，但门槛要由真实基准线和业务风险决定。
7. 评测资料也属于数据资产，外部模型评测前必须确认数据外发权限。
