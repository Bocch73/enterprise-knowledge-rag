# 第 11 步：建立可重复的 RAG 质量评测体系

## 1. 本步目标

功能测试只能证明接口能运行；检索增强生成（Retrieval-Augmented Generation，简称 RAG）评测还要回答：正确资料有没有被找到、是否排在前面、证据够不够、模型有没有正确引用和拒答。

本项目现在提供两条基线：

1. 不联网的确定性回归：稳定、免费，适合持续集成。
2. 真实端到端回归：真实调用 `qwen3.7-text-embedding`、`qwen3-rerank` 和 `deepseek-v4-flash`，验证外部模型链路。

## 2. 新名词解释

### 固定评测集

一组版本化且不随每次运行改变的问题和标准答案。只有测试对象保持不变，两个模型或两组参数的分数才可以比较。

### Top K

检索最终返回的前 K 条证据。本项目基准使用 `Top K = 5`。

### 候选数量

向量检索和关键词检索在融合前各自取回的最大数量。本项目为 30。候选多通常有利于召回，但会增加重排延迟和费用。

### 平均倒数排名

关注第一条正确资料排得有多靠前。若第一名正确得 1 分，第二名正确得 1/2 分，第三名正确得 1/3 分，再对全部问题取平均。

### 归一化折损累计增益

不仅检查是否找到正确资料，也对更靠前的正确结果给更高分，并与理想排序比较。英文常写作 Normalized Discounted Cumulative Gain。

### 重排

第一阶段先快速召回一批候选，第二阶段让更精确的模型同时阅读问题和候选文本并重新排序。本项目使用 `qwen3-rerank`。

### 证据充分性判断

不是“搜到内容”就一定应该回答。系统检查重排最高分是否达到阈值 `0.54`；未达到时不调用生成模型，直接安全拒答。该阈值来自当前固定数据集的校准，换领域或模型后必须重新评测。

### 质量门禁

一组必须达到的最低指标。任一关键指标低于阈值，评测命令以失败状态结束，持续集成就能阻止质量退化。

### 第 95 百分位延迟

把请求耗时从小到大排列，95% 的请求不超过这个值。它比平均值更能显示慢请求情况。

### 调用编号

外部服务为一次请求返回的唯一标识。出现争议、费用异常或服务故障时，可以拿调用编号到提供商侧排查。

### 有限重试与熔断器

有限重试只对限流、超时和服务器暂时故障再次请求，并设置最大次数和指数退避。熔断器在连续失败达到阈值后暂时停止外部调用，避免故障扩散和无意义费用；恢复窗口到期后只放行少量探测请求。

## 3. 评测数据

- 数据集：[company-policy-v1.json](../evaluation/datasets/company-policy-v1.json)
- 数据集版本：`2.0.0`
- 虚构制度文档：9 份
- 固定问题：135 个
- 可回答问题：108 个
- 应拒答问题：27 个

每个可回答问题都标注正确文件和答案必须包含的词语；不可回答问题明确标记为空来源。文件的安全散列摘要也写入数据集，防止语料被悄悄改动后仍与旧报告比较。

## 4. 真实执行链路

```text
迁移隔离测试数据库
  → 注册临时用户并创建知识库
  → 上传 9 份虚构文档
  → 按 800 字符、重叠 120 字符分块
  → Qwen 生成 1024 维文档向量
  → 对每个问题执行向量检索 + 关键词检索
  → 倒数排名融合 30 个候选
  → Qwen 重排前 5 条
  → 最高分与 0.54 比较
  → 证据充分时调用 DeepSeek，否则直接拒答
  → 校验引用并聚合指标
  → 输出 JSON 报告
```

评测程序只允许使用数据库名以 `_test` 结尾的隔离数据库，避免误删开发或生产数据。

## 5. 怎样运行

### 不联网的完整回归

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run-reference-evaluation.ps1 `
  -Mode full `
  -EmbeddingProvider deterministic `
  -RerankProvider deterministic `
  -GenerationProvider deterministic `
  -Output .\evaluation\reports\reference-deterministic-full-v2.json
```

这里的三个 `deterministic` 都是确定性测试替身。同样输入始终产生同样输出，不依赖网络和密钥，适合每次提交前运行，但不能代表真实模型能力。

### 真实端到端回归

先确认 `backend/.env.deepseek` 已配置 `DASHSCOPE_API_KEY`、`DEEPSEEK_API_KEY` 和当前业务空间地址，再运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run-reference-evaluation.ps1 `
  -Mode full `
  -EmbeddingProvider configured `
  -RerankProvider configured `
  -GenerationProvider configured `
  -Output .\evaluation\reports\reference-qwen37-rerank-deepseek-v4-flash-full-v2.json
```

`configured` 表示使用配置文件中的真实提供者。这会把虚构测试资料发给阿里云百炼和 DeepSeek，并产生少量费用。

## 6. 每次报告保存什么

报告模式版本为 `2.0`，主要包括：

- 数据集名称、版本、安全散列摘要和每份语料摘要；
- 分块大小 `800`、重叠 `120`；
- 候选数量 `30`、倒数排名融合常数 `60`、最终 `Top K = 5`；
- 嵌入模型、向量维度、重排模型和生成模型；
- 证据阈值、上下文字符预算、温度、最大输出词元；
- 提示词版本 `grounded-answer-v2`；
- 本次采用的模型单价快照；
- 每次调用的阶段、提供商、模型、调用编号、输入输出词元、重试次数、延迟、成功状态和估算费用；
- 每道题的检索、证据判断、回答、引用和失败原因；
- 聚合指标与质量门禁结果。

调用日志只保存元数据，不保存密钥、访问令牌、完整提示词或完整文档内容。费用是估算值，最终金额以服务商账单为准。

## 8. 保留的失败样本

真实报告没有隐藏失败：

1. `unanswerable-volunteer-leave` 的最高重排分数为 `0.578733`，超过 `0.54`，因此证据判断误认为充分；DeepSeek 最终仍正确拒答。
2. `hotel-cap-4` 检索到了正确差旅制度，最高重排分数为 `0.7853`，但 DeepSeek 对“700 元是否需要额外审批”错误拒答。

这说明证据阈值只能控制“是否值得交给生成模型”，不能替代生成质量评测。下一轮可增加难负例、按领域校准阈值，并改进答案标签和提示词。

## 9. 运行保护与监控

Qwen 嵌入、Qwen 重排和 DeepSeek 生成共享以下保护原则：

- 最多尝试 3 次；
- 仅对超时、限流和明确的服务器暂时故障重试；
- 使用指数退避，默认从 0.25 秒逐步增加，最大 2 秒；
- 连续失败 5 次后打开熔断器，默认 30 秒后进入半开探测；
- Prometheus 暴露调用总数、重试总数、调用延迟和估算费用；失败率可由成功与失败调用计数计算；
- 内存账本保存近期调用的内容无关元数据，评测结束时写入报告。

这些参数都可通过环境变量修改。多进程生产部署时，内存熔断状态互不共享，后续可迁移到 Redis 或网关层统一治理。

## 10. 当前边界

1. 评测资料是 9 份短小虚构 Markdown 文档，不代表真实企业数据分布。
2. 尚未覆盖扫描件、复杂表格、超长文档、多轮问答和高并发压测。
3. 重排分数只适合在同一次请求的候选之间比较；当前 `0.54` 阈值是项目数据上的经验校准值。
4. 模型价格会变化，报告记录的是运行时配置的单价快照，不是永久报价。
5. 真实企业资料发往外部模型前，必须完成权限、隐私、合同和数据驻留审查。

## 12. 本步知识点总结

- 固定数据、固定标签、固定参数和版本化报告，才构成可比较的基准线。
- 检索、重排、证据判断和生成必须分别评测，否则失败时无法定位责任层。
- 证据阈值要同时观察可回答问题接受率和不可回答问题拒绝率，不能只优化一个方向。
- 真实报告必须记录模型版本、提示词版本、参数、调用编号和费用，结果才可复现、可审计。
- 有限重试处理短暂故障，熔断器阻止持续故障扩散；二者不能替代超时、限流和监控。
- 小型虚构回归集适合工程比较，不等于生产业务准确率。
