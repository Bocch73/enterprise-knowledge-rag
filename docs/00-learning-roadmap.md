# 学习与开发路线

> 当前进度：第 14 步已完成。项目已经具备完整面试演示、简历描述、架构答辩、综合题库和最终检查清单；全部工程与学习产物进入最终本地 Git 提交阶段。

## 全程采用的企业开发闭环

每个功能都按以下顺序推进：需求说明 → 技术设计 → 拆分任务 → 建立开发分支 → 编码与自动化测试 → 代码检查 → 合并 → 更新文档 → 形成可演示版本。

- **开发分支**：从主线代码复制出一条独立工作线，功能完成并检查后再合回主线，避免未完成代码影响稳定版本。
- **自动化测试**：由程序自动执行的检查，用来证明功能符合预期并防止旧功能被新改动破坏。
- **代码检查**：在合并前检查代码风格、类型、安全风险和逻辑问题。
- **可演示版本**：能够稳定运行、可以展示明确功能的一次阶段性成果。

## 阶段路线

| 步骤 | 主题 | 主要产物 | 面试能力 |
|---|---|---|---|
| 1 | 项目立项 | 项目章程、范围、路线、术语表 | 能说明业务问题和项目边界 |
| 2 | 开发环境与仓库规范 | Python、容器环境、版本控制、提交规范 | 能说明团队如何协作 |
| 3 | 需求与总体架构 | 用例、质量要求、架构图、架构决策记录 | 能做技术选型和权衡 |
| 4 | 后端最小骨架 | 健康检查接口、配置、日志、单元测试 | 能搭建可维护服务 |
| 5 | 数据库与身份权限 | 用户、知识库、角色、数据库迁移 | 能解释数据一致性和权限边界 |
| 6 | 文档摄取 | 上传、校验、解析、版本、异步任务 | 能处理耗时任务和失败恢复 |
| 7 | 分块与向量索引 | 文本分块、向量表示、索引写入 | 能解释检索增强生成的数据准备 |
| 8 | 混合检索 | 语义检索、关键词检索、结果融合、重排 | 能解释召回率与精确率权衡 |
| 9 | 带引用的问答 | 提示词、拒答、流式回答、引用校验 | 能降低无依据回答风险 |
| 10 | 前端工作台 | 登录、知识库、上传、检索、对话页面 | 能展示完整产品闭环 |
| 11 | 质量评测 | 评测集、检索指标、回答质量、实验报告 | 能用数据证明效果 |
| 12 | 企业级加固 | 缓存、限流、审计、安全、可观测性 | 能讨论稳定性与安全性 |
| 13 | 持续集成与部署 | 容器编排、流水线、发布和回滚说明 | 能说明上线流程 |
| 14 | 面试交付 | 演示脚本、简历描述、架构答辩、问题库 | 能独立讲完整项目 |

## 路线完成后的使用方式

1. 按[第 14 步教程](14-interview-delivery.md)建立项目叙述方法。
2. 按[演示脚本](delivery/demo-script.md)至少完整排练两次。
3. 从[综合题库](interview/14-project-defense.md)随机抽题，不背稿地解释原因、证据、代价和边界。
4. 在真正推送远程仓库后观察首次持续集成结果，再决定是否添加构建状态徽章。
5. 只有完成真实容器部署和恢复演练后，才更新对应项目边界。

## 重要原则

1. 先做一个端到端可运行的小版本，再逐步增加企业能力。
2. 所有效果数据都由真实实验产生，不编造准确率或性能数字。
3. 密钥和密码只放在本地环境配置中，永远不提交到版本库。
4. 每个关键技术选择都记录原因、替代方案和代价。
5. 每一步必须有验证证据；“代码写完”不等于“功能完成”。
