# 项目章程：Enterprise Knowledge RAG

## 1. 项目定位

为中型企业构建一个私有知识库问答平台。员工上传公司制度、产品手册和常见问题文档后，可以用自然语言提问；系统检索相关原文，让大语言模型依据原文生成答案，并返回可以核对的来源引用。

**检索增强生成**（Retrieval-Augmented Generation）是一种先从外部资料中检索证据，再把证据交给大语言模型生成回答的方法。它不是训练一个新模型，而是在回答时给模型补充企业自己的资料。

## 2. 目标用户和角色

- **系统管理员**：管理用户、系统配置和运行状态。
- **知识库所有者**：创建知识库、管理成员和删除知识库。
- **知识库编辑者**：上传、更新和删除文档。
- **知识库查看者**：检索和提问，但不能修改资料。

角色设计体现“最小权限原则”：每个人只获得完成工作所必需的最低权限。

## 3. 核心业务流程

1. 用户登录并创建知识库。
2. 编辑者上传文档。
3. 系统校验文件，解析文本，将长文本切成较小片段。
4. 系统为片段生成向量表示并建立检索索引。
5. 查看者输入问题。
6. 系统在当前用户有权访问的资料中检索相关片段。
7. 大语言模型依据片段生成答案。
8. 页面展示答案、来源引用、耗时和必要的错误提示。
9. 管理人员可以审计操作记录并查看质量评测结果。

## 4. 第一版必须完成的功能

- 用户注册、登录和基于角色的访问控制。
- 创建、查看、修改、删除知识库。
- 上传 PDF、Word 和 Markdown 文档。
- 文档解析、分块、异步索引、进度和失败重试。
- 关键词检索与向量检索的混合检索。
- 带引用的问答、无证据时拒绝回答、多轮会话。
- 检索质量与回答质量评测。
- 结构化日志、健康检查、基础监控和审计记录。
- 自动化测试、持续集成、容器化部署和操作文档。

## 5. 第一版暂不实现

- 不训练或微调大语言模型。
- 不处理音频、视频和手写扫描件。
- 不开发原生手机应用。
- 不一开始就采用由大量独立服务组成的微服务架构。
- 不承诺互联网规模或跨地域容灾。

明确“不做什么”可以防止范围不断扩大，这在项目管理中叫做“范围蔓延”。

## 6. 已确认技术路线

技术选择已经在第 3 步通过架构决策记录确认，未来改变时必须新增替代决策并保留历史：

- 后端：Python + FastAPI。
- 前端：Vue 3 + TypeScript。
- 关系数据库：PostgreSQL。
- 向量检索扩展：pgvector。
- 缓存和任务消息：Redis。
- 后台任务：Celery。
- 数据库迁移：Alembic。
- 自动化测试：pytest、Vitest 和端到端浏览器测试。
- 运行与部署：Docker Compose，后期补充生产部署设计。

完整组件职责、风险和资料依据见 [技术栈与职责](architecture/technology-stack.md)，选择过程见 [架构决策记录](architecture/decisions/README.md)。Docker 安装当前主动延期，不影响前期开发，但正式异步任务和完整部署仍需要 Linux 容器或 Linux 环境。

我们采用“模块化单体”作为起点：系统是一个主要后端应用，但内部按身份、知识库、摄取、检索、问答、评测等模块严格分开。它适合当前单开发者和单机交付约束，同时保留以后拆分服务的边界。

## 7. 企业级质量目标

- **安全性**：越权访问必须被阻止；密码安全存储；上传文件严格校验；密钥不得进入版本库。
- **可靠性**：耗时任务失败可重试；重复请求不会产生错误的重复数据；关键依赖有健康检查。
- **可维护性**：模块边界清楚；核心逻辑有类型说明和测试；数据库结构可迁移。
- **可观测性**：能通过日志、指标和请求追踪定位一次问答为何失败或变慢。
- **可解释性**：答案包含原文引用；检索过程保留分数和来源信息。
- **可评测性**：固定数据集、固定配置、原始结果和汇总报告都能追溯。

这些目标以后会转化为可测量的验收指标。本阶段不提前编造响应时间或准确率。

## 8. 第一版完成标准

项目只有同时满足以下条件才算完成：

1. 新电脑可以按照文档启动全部服务。
2. 演示者能走通“登录 → 建库 → 上传 → 索引 → 提问 → 查看引用”的完整流程。
3. 未授权用户无法读取受限知识库和文档。
4. 自动化测试和代码质量检查全部通过。
5. 有真实评测集、原始输出和可复现实验报告。
6. 有部署、备份、恢复、故障排查和安全说明。
7. 有架构图、数据库图、接口文档、运行手册和可复现验证命令。

## 9. 已知风险

| 风险 | 可能影响 | 初步应对 |
|---|---|---|
| Docker 当前主动延期 | 暂时无法运行完整数据库、缓存和 Linux 工作进程组合 | 第 4 步先完成无外部依赖的后端骨架；进入集成阶段前重新确认 |
| 模型接口需要费用或网络 | 无法稳定演示 | 提供可替换模型接口和本地确定性测试替身 |
| 文档解析质量不稳定 | 检索不到正确原文 | 保留解析结果、分块预览和评测集 |
| 大语言模型编造内容 | 答案不可信 | 证据阈值、拒答、引用校验和评测 |
| 功能过多导致做不完 | 项目长期无法闭环 | 每阶段形成可运行小版本，严格控制范围 |
