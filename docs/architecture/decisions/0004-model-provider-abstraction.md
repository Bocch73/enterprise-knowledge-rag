# ADR-0004：模型通过 Provider 抽象接入

- 状态：Accepted
- 日期：2026-08-26
- 决策者：项目开发者

## 背景

大语言模型、向量模型和重排模型可能来自不同供应商。面试演示和自动化测试也不能依赖持续联网、真实密钥或付费额度。

## 候选方案

1. 在业务代码中直接调用一个供应商的软件开发工具包。
2. 全部通过一个大型人工智能框架封装。
3. 为生成、向量和重排分别定义小型 Provider 接口，由适配器实现。

**Provider** 在本项目中表示能力提供者接口，例如“把文本转换为向量”，而不是某家供应商的具体调用代码。

## 决定

定义三个小型异步接口：生成 Provider、向量 Provider 和重排 Provider。提供至少一个真实兼容实现和一个本地确定性测试替身。

## 原因

- 测试可以离线、快速且结果可重复。
- 切换供应商不需要修改检索和问答业务规则。
- 可以统一超时、重试、令牌、成本和错误记录。
- 小接口比引入大型框架更容易理解和面试讲解。

## 后果

积极后果：降低供应商绑定，增强测试和故障处理能力。

代价：需要自己维护能力差异和统一错误模型；最低公共接口可能无法暴露所有供应商特性。

## 第 9 步实施证据

- 生成 Provider 已由 `DeepSeekGenerationProvider` 和离线测试替身实现。
- 当前默认模型为可配置的 `deepseek-v4-flash`。
- 适配器统一处理超时、连接、鉴权、余额、限流和无效响应。
- 业务问答服务没有导入 DeepSeek 的具体协议细节。
- 真实冒烟测试确认官方接口和当前模型可用。

## 重新评估条件

- 多数供应商出现稳定且统一的行业接口。
- 自建适配器维护成本明显超过成熟框架收益。
- 需要复杂工作流编排而小型接口无法表达。
