# ADR-0002：使用 PostgreSQL 和 pgvector

- 状态：Accepted
- 日期：2026-08-26
- 决策者：项目开发者

## 背景

系统既要保存用户、权限、文档版本和会话等关系数据，也要进行关键词检索和向量相似度检索。当前电脑存在 SQL Server 2008 R2 和 MySQL 8.0，但没有适合本项目的一体化本地向量能力。

## 候选方案

1. PostgreSQL + pgvector：一个数据库处理关系、全文和向量查询。
2. MySQL 8.0 + 独立向量数据库：分别保存业务和向量数据。
3. SQL Server 2008 R2：复用现有服务。
4. SQL Server 2025：升级后使用新向量能力。
5. 只使用独立向量数据库：把全部业务数据也放入向量系统。

## 决定

第一版选择 PostgreSQL 17 与 pgvector 0.8 系列。数据规模小时先使用精确向量检索；建立评测基线后再决定是否启用 HNSW 近似索引。

**HNSW** 的完整名称是 Hierarchical Navigable Small World，即分层可导航小世界图。它用多层图结构加速近似最近邻搜索，但需要更多构建时间和内存。

## 原因

- 权限条件、业务元数据和向量可以在同一条数据库查询中组合。
- PostgreSQL 自带全文检索，pgvector 支持精确和近似向量搜索。
- 事务、备份、连接管理和审计只围绕一个主要数据库展开。
- 参考项目和大量开源检索增强生成工程有可学习实现。

## 未选择现有数据库的原因

- 当前 SQL Server 版本为 10.50.1600.1，即 SQL Server 2008 R2 RTM，已经停止官方支持且无原生向量能力。
- 当前普通 MySQL 8.0 可以保存关系数据，但若另加向量数据库，会增加双写、删除同步和权限一致性问题。
- SQL Server 2025 的向量能力较新，近似向量索引仍需谨慎评估；升级现有旧实例也可能影响其他应用。

## 后果

积极后果：数据模型统一、权限过滤更直接、备份恢复链路较少。

代价：需要安装 PostgreSQL 和 pgvector；随着向量规模增长，数据库内存和索引参数需要专门调优。

## 重新评估条件

- 向量数量或查询负载超过单机 PostgreSQL 能力。
- 需要多模态或超高维索引，而 pgvector 无法满足。
- 组织已经有成熟、合规且低成本的专用向量平台。
- SQL Server 2025 向量能力稳定且企业环境要求统一使用微软数据栈。
