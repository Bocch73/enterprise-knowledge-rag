# 第 2 步面试题：开发环境与协作流程

## 1. 为什么每个 Python 项目都应该使用虚拟环境？

**参考答案：** 不同项目可能依赖同一个库的不同版本。虚拟环境把解释器入口和第三方依赖隔离在项目目录中，避免升级一个项目的依赖时破坏其他项目，也让开发和测试使用明确的依赖集合。生产可复现还需要进一步锁定依赖版本，虚拟环境本身并不能完全保证可复现。

## 2. Git 的工作区、暂存区和版本库有什么区别？

**参考答案：** 工作区是当前磁盘上的文件；暂存区保存下一次提交准备包含的改动；版本库保存已经提交的历史快照。开发者可以只暂存本次任务相关的文件，避免把调试内容或无关改动混进同一个提交。

## 3. `git add`、`git commit` 和 `git push` 分别做什么？

**参考答案：** `git add` 把改动选择进暂存区；`git commit` 在本地创建历史快照；`git push` 才把本地提交发送到远程版本库。这三个动作对应选择改动、保存本地历史和共享远程历史。

## 4. 为什么功能开发要使用分支？

**参考答案：** 分支为一组改动提供独立工作空间，不影响稳定主线，并允许通过拉取请求进行自动化检查和代码审查。每个分支只处理一个主题，也更容易撤销、推迟或单独合并。

## 5. 拉取请求中应该提供什么？

**参考答案：** 应说明要解决的问题、主要改动、测试和手动验证证据、潜在风险、回滚方法，以及安全、权限、数据库和接口影响。审查者需要据此判断改动是否正确且可以安全合并。

## 6. 为什么不能把 `.env` 文件提交到 Git？

**参考答案：** `.env` 通常包含数据库密码和模型访问密钥。一旦进入 Git 历史，即使后来删除，旧提交中仍可能保留，远程平台和其他开发者也可能已经复制。正确做法是提交不含真实值的 `.env.example`，真实密钥通过本地配置或专门的密钥管理系统提供。

## 7. 为什么不应该继续使用已经停止维护的 Node.js 版本？

**参考答案：** 停止维护后不再接收安全漏洞修复和常规错误修复，第三方工具也会逐步停止兼容。企业项目使用这种版本会增加安全、合规和依赖升级风险，因此应选择仍在长期支持期的版本并记录升级计划。

## 8. 为什么 Git 作者身份要使用真实或正式的隐私邮箱？

**参考答案：** 作者姓名和邮箱会写入每个提交并永久存在于历史中，它们用于责任追踪和远程平台账号关联。伪造临时身份会让历史不可信，而直接暴露私人邮箱又可能带来隐私问题，所以应使用正式展示名和 GitHub 验证邮箱或平台提供的隐私邮箱。
