# 第 5 步面试题与参考答案：数据库、认证与授权

建议使用“定义 → 项目实现 → 安全或工程取舍”的结构回答。

## 1. 为什么不用 `postgres` 超级管理员运行后端？

**参考答案：** 超级管理员可以绕过几乎全部数据库权限检查，一旦应用发生结构化查询注入或凭据泄露，攻击范围会扩大到整个数据库服务器。本项目只在初始化时使用超级管理员，运行时使用不能创建数据库、不能创建角色、不能绕过安全策略的 `rag_app`。这是最小权限原则。

## 2. 为什么正式库和测试库要分开？

**参考答案：** 集成测试会创建和清理数据，如果误连正式库会造成数据破坏。本项目使用独立账户和 `rag1_test`，清理前还在代码和脚本中验证名称必须以 `_test` 结尾。隔离和自动保护比依赖开发者记忆更可靠。

## 3. SQLAlchemy、Psycopg 和 Alembic分别负责什么？

**参考答案：** SQLAlchemy 提供 Python 数据模型、查询表达式、会话和事务；Psycopg 是与 PostgreSQL 通信的底层驱动；Alembic 把数据库结构修改保存为有顺序的版本。三者分别解决数据访问、数据库连接和结构演进问题。

## 4. 什么是数据库迁移？为什么不能上线时自动建表？

**参考答案：** 数据库迁移是可审查、可重复执行的结构变更历史。自动建表只会创建缺少的表，通常不能安全表达重命名、数据转换、索引并发构建或回退，也没有明确版本。项目使用 Alembic，并在质量门禁中运行漂移检查。

## 5. 什么是迁移漂移？

**参考答案：** 漂移是代码模型和实际数据库结构不一致，例如模型增加了字段但没有迁移。它会导致开发机正常、其他环境运行时报错。本项目用 `alembic check` 比较元数据和正式本地库，发现时间字段时区和重复约束问题后进行了修正。

## 6. 为什么使用异步数据库会话？

**参考答案：** 网络接口经常等待数据库输入输出，异步会话允许线程在等待期间处理其他请求，适合后续还会调用模型和存储服务的系统。它不会让复杂计算自动变快。Windows 下 Psycopg 异步模式需要选择器事件循环，因此项目提供统一的 `app.server` 启动入口。

## 7. 主键、外键和索引有什么区别？

**参考答案：** 主键唯一标识一行；外键保证引用的父记录存在；索引用额外空间和写入成本换取更快查询。本项目用户和知识库使用通用唯一识别码主键，成员表使用复合主键，所有者和成员字段使用外键，邮箱使用小写表达式唯一索引。

## 8. 为什么邮箱既在应用中转小写，又在数据库建立唯一索引？

**参考答案：** 应用规范化改善用户体验，但并发请求或其他写入程序可能绕过应用层检查。数据库唯一索引是最终一致性防线。服务捕获数据库唯一冲突并转换成稳定的 409 业务错误，解决并发竞态条件。

## 9. 密码哈希和加密有什么区别？

**参考答案：** 加密设计为持有密钥时可以还原原文，密码哈希设计为单向验证，不能还原。本项目用 Argon2 和随机盐值，只保存哈希；登录时验证候选密码。即使数据库泄露，攻击者也不能直接读取明文，但仍可能离线猜测，所以用户密码必须足够长且唯一。

## 10. 为什么未知邮箱也执行密码哈希？

**参考答案：** 如果未知邮箱立即返回，而已知邮箱需要执行昂贵哈希，攻击者可以根据时间差枚举已注册邮箱。本项目对未知用户执行一次假的 Argon2 验证，并让错误状态和消息相同，降低时间侧信道风险。

## 11. JSON 网络令牌是加密的吗？

**参考答案：** 本项目使用的 JSON 网络令牌是签名而不是加密。载荷可以被读取，但篡改后签名验证会失败。因此不能在令牌里放密码或私密文档。项目校验签发者、接收者、用途、签发时间、过期时间和唯一编号。

## 12. 为什么令牌中不直接保存角色并完全相信它？

**参考答案：** 角色变化后，旧令牌中的角色会一直有效到过期。本项目令牌只用用户编号标识身份，每次请求重新查询用户和角色，因此停用账户或调整角色能立即生效。代价是多一次数据库查询，后续可以使用短期缓存并设计可靠失效机制。

## 13. 身份认证和权限授权有什么区别？

**参考答案：** 身份认证确认“请求者是谁”，例如密码登录和令牌校验；权限授权确认“这个人能做什么”，例如只有知识库所有者能管理成员。认证成功不等于对所有数据都有权限。

## 14. 什么是基于角色的访问控制？

**参考答案：** 它把权限授予角色，再把角色分配给用户，减少逐用户维护权限的成本。本项目有 `admin/member` 全局角色，也有 `owner/editor/viewer` 知识库资源角色。两层模型避免全局管理员概念和内容协作权限混在一起。

## 15. 什么是水平越权和垂直越权？项目如何防止？

**参考答案：** 水平越权是访问另一个同级用户的资源，垂直越权是普通用户执行管理员或所有者操作。项目在 SQL 查询中按当前用户加入知识库成员条件，无权资源统一返回 404；管理成员要求所有者或管理员；管理员接口显式检查全局角色。自动化测试覆盖两类越权。

## 16. 为什么无权访问知识库时返回 404 而不是 403？

**参考答案：** 403 会告诉攻击者这个编号对应的资源确实存在。对私有资源统一返回 404，可以减少资源枚举信息泄露。对于已经知道资源存在但权限不足的操作，例如查看者管理成员，则返回 403 更清楚。

## 17. 什么是事务，本项目在哪里需要？

**参考答案：** 事务保证一组修改全部成功或全部撤销。创建知识库时必须同时创建所有者成员关系；注册时必须同时创建用户和默认角色关系。任一步失败都不能留下半成品。SQLAlchemy 会话负责提交和回滚，数据库约束负责最终完整性。

## 18. 为什么测试覆盖率高仍不能证明权限绝对安全？

**参考答案：** 覆盖率只说明代码被执行，不证明所有身份组合、竞态条件和攻击手法都覆盖。项目同时测试令牌篡改、过期、账户停用、重复邮箱、水平越权、垂直越权和真实 PostgreSQL，但生产前还需要安全评审、依赖扫描、模糊测试、限速和渗透测试。
