# 第 3 步面试题：需求与总体架构

## 1. 功能需求和非功能需求有什么区别？

**参考答案：** 功能需求描述系统做什么，例如上传文档、检索和带引用问答；非功能需求描述系统以什么质量运行，例如权限安全、延迟、可靠性、可观测性和恢复能力。两者都需要可验证条件。只有功能没有质量约束，通常只能得到演示程序，而不是可运行的企业系统。

## 2. 为什么选择模块化单体而不是微服务？

**参考答案：** 当前只有一个开发者，业务边界仍在验证，模块之间还存在事务一致性需求。模块化单体能减少网络通信、部署、分布式事务和监控复杂度，同时通过领域模块保留清晰边界。如果以后出现独立扩缩容、团队独立发布或强故障隔离需求，再根据证据拆分服务。

## 3. 为什么选择 PostgreSQL + pgvector？

**参考答案：** 系统需要同时处理用户权限、文档元数据、全文检索和向量检索。PostgreSQL 提供事务和全文检索，pgvector 提供精确与近似向量搜索。把权限条件和向量查询放在同一数据库中，可以减少 MySQL 加独立向量库产生的双写、删除同步和权限不一致问题。

## 4. 为什么不用电脑里现有的 SQL Server？

**参考答案：** 检测到的是 SQL Server 2008 R2 RTM，已经停止官方支持，也没有原生向量数据类型和相似度搜索。为了复用旧环境而放弃安全维护和核心检索能力，不符合新企业项目的风险控制。现有实例应该保持不动，避免影响可能依赖它的旧应用。

## 5. 为什么 Redis 不能保存唯一任务状态？

**参考答案：** Redis 在本项目中是缓存和消息代理，内容可能因过期、故障或清理而消失。消息交付也不等于任务完成。数据库需要持久保存任务编号、阶段、尝试次数和最终结果，Redis 丢失后才能对账并重新投递。业务状态以 PostgreSQL 为准。

## 6. 为什么采用混合检索？

**参考答案：** 向量检索擅长同义表达和语义相似，但可能忽略制度编号和产品型号；关键词检索擅长精确词语，但不理解改写和同义问题。两路融合可以覆盖更多问题类型。使用倒数排名融合是因为两路原始分数不在同一量纲，按名次融合更简单且可解释。

## 7. 精确向量检索和近似向量检索如何选择？

**参考答案：** 精确检索计算所有候选距离，召回完整但数据量大时更慢；近似索引只探索可能相关的部分空间，提高速度但可能漏掉正确结果。项目初期数据少，应先用精确检索建立质量基线。数据增长后再比较延迟、内存和召回率，不能因为 HNSW 流行就默认启用。

## 8. 为什么文档摄取要异步执行？

**参考答案：** 文档解析、分块、生成向量和建索引可能耗时很长。同步放在上传请求中容易超时，也无法合理展示进度和恢复失败。异步任务让接口快速返回任务编号，工作进程独立执行、重试和扩展。但消息可能重复，所以任务必须幂等并使用数据库状态控制并发。

## 9. 什么是依赖倒置？在项目中如何体现？

**参考答案：** 依赖倒置是核心业务依赖抽象能力，而不是直接依赖具体数据库或供应商。项目中的问答服务只依赖生成 Provider 接口，PostgreSQL、Redis和具体模型由外围适配器实现。测试可以注入本地替身，切换供应商也不需要修改核心业务规则。

## 10. 为什么权限过滤必须在检索之前完成？

**参考答案：** 如果先检索或先调用模型再过滤页面结果，未授权内容已经进入缓存、日志或外部模型，数据泄露已经发生。正确做法是让权限范围成为数据库检索条件，并保证关键词、向量、重排、缓存和引用阶段使用相同边界。

## 11. 服务级别目标、恢复点目标和恢复时间目标分别是什么？

**参考答案：** 服务级别目标是团队希望达到的性能或可靠性指标；恢复点目标表示最多能接受丢失多长时间的数据；恢复时间目标表示故障后希望多快恢复服务。它们必须根据业务价值和成本制定，并通过监控和恢复演练验证。

## 12. 架构决策记录有什么价值？

**参考答案：** 它记录决定发生时的约束、候选方案、最终选择、代价和重新评估条件。以后团队可以理解当初为什么选择，而不是把某个技术当作永远正确。如果方向改变，应新增替代记录，保留历史，而不是直接改掉旧文档。
