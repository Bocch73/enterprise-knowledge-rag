# 第 10 步面试题与参考答案：Vue 企业工作台

建议按照“用户需求 → 前端实现 → 安全边界 → 测试证据”回答。

## 1. 为什么选择 Vue 3？

**参考答案：** 项目技术决策阶段已经选定 Vue 3 + TypeScript。Vue 的单文件组件和 Composition API 适合把知识库、文档、任务和问答拆成独立组件，官方生态提供 Router 和 Pinia。选型不是说 Vue 永远优于 React，而是团队熟悉度、官方工具链、交付效率和维护成本的权衡。

## 2. 什么是单页应用？

**参考答案：** 浏览器初次加载一个 HTML 外壳，后续由 JavaScript 根据路由替换组件，不为每次导航重新加载完整页面。我的项目有登录、注册和工作台路由，Vite 负责开发与构建。需要服务器把未知前端路径回退到 `index.html`，否则刷新子路径会 404。

## 3. 为什么使用 TypeScript？

**参考答案：** 后端已经有明确的用户、知识库、任务和引用结构，TypeScript 能在编译时检查前端字段和函数参数，降低重构风险并改善编辑器提示。它不能验证真实网络响应，所以后续还可增加运行时模式校验。

## 4. 组件怎样拆分？

**参考答案：** 页面级组件负责路由场景，业务组件负责知识库侧栏、文档和问答。父组件用属性传数据，子组件发事件通知选择或创建。网络逻辑集中在 service，登录跨页面状态放 Pinia，避免所有代码堆在一个组件。

## 5. 为什么只把认证状态放 Pinia？

**参考答案：** 当前真正跨页面共享的状态主要是用户和令牌。知识库、文档和任务以服务器为真实来源，由工作台或组件按需读取。把所有服务器数据长期复制进全局 Store 容易产生缓存失效和更新同步问题，规模扩大后再引入专用服务器状态方案。

## 6. 登录令牌保存在哪里？

**参考答案：** 当前保存在 `sessionStorage`，关闭标签页后清除，没有放长期 `localStorage`。页面刷新时用 `/auth/me` 验证令牌，失败就清理。会话存储仍可被同源 JavaScript 读取，所以必须防御跨站脚本；生产可评估 Secure、HttpOnly、SameSite Cookie 和跨站请求伪造控制。

## 7. 路由守卫是不是安全控制？

**参考答案：** 不是最终安全边界。它只防止普通用户在界面上进入不合适页面，浏览器代码可被修改。FastAPI 每个接口仍验证令牌和知识库成员权限。前端隐藏上传按钮也不能代替服务端查看者权限检查。

## 8. 为什么统一封装 Fetch？

**参考答案：** 统一添加认证、JSON 内容类型、解析统一错误、保留请求编号和处理网络失败，组件只关心业务状态。流式问答解析也放在同一层。这样后端错误结构或认证方式变化时不用修改所有页面。

## 9. 文件上传为什么不手工设置 multipart 内容类型？

**参考答案：** 浏览器用 `FormData` 自动生成 multipart 边界，并把边界写入内容类型。手工写成 `multipart/form-data` 却没有匹配边界会让后端无法解析。前端只附加文件和标题，浏览器负责协议细节，后端仍重新验证文件。

## 10. 摄取任务状态怎样更新？

**参考答案：** 上传后保存任务编号，每 2 秒查询一次任务接口，显示阶段与进度。任务完成或失败就停止，组件销毁和切换知识库也取消计时器。轮询实现简单，代价是空请求较多；高并发可评估服务器发送事件、WebSocket 或退避间隔。

## 11. 怎样解析服务器发送事件？

**参考答案：** Fetch 返回 `ReadableStream`，`TextDecoder` 把二进制块转成字符串。网络块不等于事件边界，所以把未完成内容留在缓冲区，按空行拆分事件，再读取 `event:` 和 `data:`。项目处理回答片段、引用和完成三种事件。

## 12. 流中断怎样处理？

**参考答案：** 只有收到 `done` 才标记完整成功。如果连接结束但缺少完成事件，网络层抛出 `incomplete_stream`，页面显示错误。后端当前先完整校验和保存再流式发送，所以通常已有持久记录；未来上游逐词元流式还需定义取消和不完整记录状态。

## 13. 为什么不直接在后端开启 CORS 允许所有来源？

**参考答案：** 本地由 Vite 把 `/api` 代理到 8000 端口，浏览器看到的是同源请求；生产由反向代理统一域名。允许所有来源会扩大浏览器攻击面，特别是携带凭证时。确需跨域时应该精确列出可信来源、方法和请求头。

## 14. Vite 开发服务器和生产部署有什么区别？

**参考答案：** 开发服务器提供热更新和代理，适合本地开发，不是生产入口。`npm run build` 输出压缩、带哈希文件名和代码拆分的 `dist`，应由 Nginx 等静态服务器或对象存储加内容分发网络托管，再代理 `/api`。

## 15. 什么是代码拆分？

**参考答案：** 路由组件使用动态导入，构建后登录、注册和工作台形成独立文件。浏览器先下载当前页面需要的代码，进入工作台时再加载业务包。项目生产报告显示主入口 gzip 后约 39.67 KB，工作台包 gzip 后约 5.06 KB。

## 16. 怎样做响应式布局？

**参考答案：** 桌面采用固定侧栏和两列面板，1050 像素以下把业务面板改成一列，800 以下侧栏变为顶部块，手机进一步收紧边距和上传布局。我用 1440 与 390 像素截图实际检查，而不是只写媒体查询就宣称完成。

## 17. 做了哪些可访问性工作？

**参考答案：** 表单有显式标签，图标按钮有无障碍名称，错误使用 `role=alert`，流式答案使用实时区域，标题保持层级，辅助文字可供屏幕阅读器读取，并响应减少动画偏好。完整上线还应做键盘路径、对比度工具和真实辅助技术测试。

## 18. 单元、组件和端到端测试分别证明什么？

**参考答案：** 单元测试证明令牌、错误和流解析；组件测试证明输入、事件和引用渲染；Playwright 在真实 Chrome 中证明路由、登录、知识库和问答组合流程。模拟后端让测试稳定且无费用，真实代理健康检查再证明前后端能连通。

## 19. 为什么模拟后端不能代替真实联调？

**参考答案：** 模拟返回可能与真实协议漂移，也测不到代理、序列化和服务启动问题。因此我保留 TypeScript 契约、组件测试和模拟浏览器流程，同时启动真实 Vite 与 FastAPI，通过代理请求健康接口并得到 HTTP 200。后续应增加隔离数据库的真实浏览器测试。

## 20. 遇到依赖冲突怎样处理？

**参考答案：** 官方脚手架的范围把 oxlint 解析到 1.74.0，但配套插件要求 1.73.x。没有用 `--force` 或旧同级依赖模式忽略，而是把工具对齐到兼容的 1.73.0，再安装并运行全部门禁。锁文件保留实际依赖树，npm 审计报告 0 个已知漏洞。

## 21. 为什么 `VITE_` 变量不能放密钥？

**参考答案：** Vite 会把这些变量替换进浏览器构建，任何用户都能下载和查看。前端只能保存公开配置，例如 API 路径。DeepSeek 密钥、数据库密码和 JWT 签名密钥必须留在后端环境。

## 22. 当前前端还有哪些边界？

**参考答案：** 没有成员管理、文档版本预览、任务历史、多轮会话和生产静态托管。端到端测试目前模拟后端，真实联调是无副作用健康检查。第 11 步还要用固定数据集证明检索和回答质量，第 13 步再完成部署与安全响应头。

## 23. 如何证明本步完成？

**参考答案：** 12 个单元与组件测试通过，关键逻辑语句覆盖率 94.33%、分支 80%、函数和行分别 100%；2 个 Chrome 端到端流程通过；格式、Oxlint、ESLint、严格类型和生产构建通过；桌面和手机截图完成视觉检查；最后 Vite 代理真实请求 FastAPI 健康接口返回 HTTP 200。同时记录未完成的业务页面和部署边界。
