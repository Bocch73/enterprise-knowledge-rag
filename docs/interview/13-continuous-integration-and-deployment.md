# 第 13 步面试题与参考答案：持续集成与部署

## 1. 什么是持续集成？

**参考答案：** 开发者频繁合并小变更，每次变更自动执行构建、测试、格式和类型等检查，尽早发现组合
问题。它不仅是自动跑命令，更重要的是形成统一、可重复的合并门禁。

## 2. 持续交付和持续部署有什么区别？

**参考答案：** 持续交付自动产生随时可部署的制品，但生产上线仍需批准；持续部署在门禁通过后自动
上线。本项目涉及数据库、企业文档和外部模型费用，因此采用持续交付。

## 3. 为什么质量门禁要做成可复用工作流？

**参考答案：** 普通拉取请求和版本发布调用同一份定义，可以避免检查项漂移。否则可能出现开发阶段
测试严格，而发布路径漏掉评测或迁移检查的问题。

## 4. 为什么 CI 使用真实 PostgreSQL，而不是全部 Mock？

**参考答案：** 对象关系映射、事务、行锁、全文检索、pgvector 和 Alembic 都依赖 PostgreSQL 真实行为。
Mock 适合快速单元测试，但不能证明数据库方言、扩展和迁移能够工作。

## 5. 什么是服务容器？

**参考答案：** 它是在流水线任务期间临时运行的数据库或缓存容器，任务结束后销毁。本项目用它创建
隔离的 `rag1_test`，既接近真实依赖，又不污染开发和生产数据库。

## 6. 为什么 CI 不调用 DeepSeek？

**参考答案：** 每次提交调用外部模型会产生费用、随机波动和数据外发风险，也可能因为供应商故障让
流水线不稳定。因此常规门禁使用确定性本地生成器，真实模型评测由已授权的周期或发布前实验完成。

## 7. 为什么要同时做普通测试和 RAG 质量门禁？

**参考答案：** 普通测试证明接口、权限和错误处理符合预期；RAG 门禁证明正确来源能被检索、引用和拒答
没有退化。两者解决的问题不同，不能互相代替。

## 8. `npm ci` 和 `npm install` 在流水线中有什么区别？

**参考答案：** `npm ci` 要求锁文件与依赖声明一致，先清理现有依赖并按锁文件精确安装，结果更适合
可重复构建。`npm install` 可能更新锁文件或解析出不同版本。

## 9. 什么是多阶段构建？

**参考答案：** Dockerfile 使用一个阶段安装或编译，另一个阶段只保留运行所需文件。它能减小最终镜像，
避免把编译工具、源码测试和缓存全部带入生产运行环境。

## 10. 为什么容器不能默认用 root 运行？

**参考答案：** 应用漏洞被利用时，root 会扩大攻击者在容器内的能力。非根用户、删除 capabilities、
只读文件系统和 no-new-privileges 可以限制影响范围，但仍不能代替及时修复漏洞。

## 11. 什么是容器镜像摘要？

**参考答案：** 摘要是由镜像内容计算的不可变标识。版本标签便于人理解，但标签可能被重新指向；生产
记录摘要才能精确证明部署的是哪一份内容。

## 12. 为什么不使用 latest 标签？

**参考答案：** `latest` 不能表达版本，也可能在不同时间指向不同内容，导致无法复现和回滚。生产应使用
语义化版本或镜像摘要。

## 13. 什么是软件物料清单？

**参考答案：** 软件物料清单列出制品中的操作系统包和应用依赖，帮助定位某个漏洞影响哪些镜像。它是
供应链透明度证据，但不代表列出的组件一定没有漏洞。

## 14. 什么是构建来源证明？

**参考答案：** 它记录制品由哪个源代码修订和构建过程产生，帮助验证镜像来源。它不能替代代码审查和
密钥保护，但能降低无法追溯构建来源的风险。

## 15. 为什么数据库迁移要作为独立任务？

**参考答案：** 多个应用副本同时启动迁移可能产生竞争；迁移失败后继续启动应用会让代码与结构不一致。
一次性迁移任务成功后再启动应用，边界更清晰，也便于单独查看日志。

## 16. 什么是扩展与收缩迁移？

**参考答案：** 先增加兼容结构，再迁移读写和历史数据，最后在后续版本删除旧结构。它允许新旧应用在
发布窗口内共同运行，比一次性重命名或删除列更容易回滚。

## 17. 应用回滚时为什么不能默认数据库 downgrade？

**参考答案：** 数据库降级可能删除新列、新表或新版本已经写入的数据。应用镜像通常可以快速回滚，
数据库应该依赖向后兼容迁移；确需降级时必须单独审查数据影响并准备恢复方案。

## 18. 存活检查和就绪检查的区别是什么？

**参考答案：** 存活检查判断进程是否需要重启；就绪检查判断应用和必要依赖是否可以接收流量。数据库
暂时不可用时应用可能仍存活，但应该从流量入口摘除。

## 19. 为什么数据库容器不映射 5432 端口？

**参考答案：** 只有后端、迁移和工作进程需要连接数据库。放在内部网络并不映射宿主端口可以减少攻击
面，管理访问应通过受控网络或临时运维通道完成。

## 20. 为什么 `/metrics` 不通过公共 Nginx 暴露？

**参考答案：** 指标会暴露路由、错误率、负载和依赖情况。Prometheus 应通过内部网络和独立令牌采集，
不应让互联网用户直接访问。

## 21. 有数据卷为什么还需要备份？

**参考答案：** 数据卷只让容器重建后数据继续存在，不能防止误删除、磁盘损坏、勒索软件或整个服务器
丢失。备份需要独立位置、校验、保留策略和恢复演练。

## 22. 为什么备份后必须做恢复演练？

**参考答案：** 备份文件可能损坏、缺少对象文件、权限不完整或恢复时间过长。恢复到隔离数据库并执行
业务验证，才能证明备份真正可用。

## 23. 本项目的恢复脚本有哪些安全保护？

**参考答案：** 它要求目标数据库以 `_restore` 结尾、要求重复输入目标名称、校验 SHA-256、先检查归档，
并拒绝覆盖已存在数据库。当前不会自动删除失败的演练库，以便保留诊断证据。

## 24. 如何避免两个生产发布同时运行？

**参考答案：** 使用 GitHub Actions concurrency 让同一生产环境最多一个部署任务，并配合受保护
environment 的批准规则。普通 CI 可以取消旧提交，生产发布则不应在中途被新任务随意取消。

## 25. 为什么发布工作流仍要重新跑质量门禁？

**参考答案：** 标签可能指向尚未经过完整发布检查的修订，测试历史也可能已经过期。发布前重新验证并
从该修订构建，能把门禁结果和最终制品绑定起来。

## 26. Dependabot 自动更新依赖后可以直接合并吗？

**参考答案：** 不可以。它只负责发现新版本和创建拉取请求。仍需阅读发行说明、安全影响和不兼容变化，
并通过全部测试和评测；重大数据库、模型或框架升级还要人工验证。

## 27. 为什么当前不能说“已经部署到生产”？

**参考答案：** 当前完成了工作流、镜像、Compose、密钥和运行手册，并通过本地静态测试；但还没有 Git
远程运行记录、Docker 实际构建、服务器、HTTPS、生产监控或真实回滚演练。准确表达应是“具备可验证的
生产式交付设计，真实部署仍待目标环境验收”。

## 28. 如果要扩展到多个后端实例，还缺什么？

**参考答案：** 首先把进程内限流和向量缓存迁移到 Redis 等共享服务；为 Prometheus 配置多进程或
每实例采集；把对象文件迁移到共享对象存储；验证数据库连接池总量、任务并发、会话与健康检查，再通过
负载和故障演练确定扩缩容规则。
