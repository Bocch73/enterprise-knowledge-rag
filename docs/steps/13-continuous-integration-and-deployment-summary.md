# 第 13 步知识点总结：持续集成与部署

## 完成的工程能力

- 建立后端、前端、浏览器、RAG 质量和镜像构建的可复用 GitHub Actions 门禁。
- 使用临时 PostgreSQL 17 + pgvector 0.8.6 进行真实数据库集成测试。
- 持续集成不配置 DeepSeek 密钥，确定性评测不会产生费用或外发资料。
- 版本标签通过同一套门禁后发布前后端镜像。
- 镜像包含版本、代码修订、软件物料清单和构建来源证明。
- 前后端采用多阶段构建、非根用户、健康检查和最小运行内容。
- Compose 将数据库放在内部网络，并把迁移、接口和工作进程分开。
- 密钥通过独立文件挂载，不写入镜像、YAML 或非敏感环境文件。
- 新增数据库备份、校验和只恢复到新演练数据库的安全脚本。
- 新增部署运行手册、备份恢复手册和发布回滚检查清单。

## 最重要的判断

- 本项目采用持续交付，不在没有授权服务器的情况下自动生产部署。
- 拉取请求和版本发布必须执行同一套可复用门禁。
- 真实模型评测不是每次提交都运行，避免数据外发和费用失控。
- 数据库迁移失败必须阻止应用启动，不能跳过错误继续发布。
- 应用回滚不等于数据库降级，数据库降级可能破坏数据。
- 单机 Compose 是生产式演练，不等同于多实例高可用系统。
- 没有恢复演练的备份不能当作可靠恢复证据。

## 当前验证

- 16 个新增部署专项测试通过。
- 5 份持续集成和部署 YAML 通过语法与格式解析。
- 后端 105 个测试通过，分支覆盖率 83.26%，Ruff、Mypy 和 Alembic 检查通过。
- 前端 12 个单元测试和 2 个 Chrome 浏览器流程通过，语句覆盖率 94.33%、分支覆盖率 80%。
- 免费的确定性完整 RAG 门禁通过，Top 3 命中率、平均倒数排名和归一化折损累计增益均为 1.000。
- 本步没有调用 DeepSeek，没有外发数据或产生模型费用。
- 本机不需要 Docker，未启动任何容器。
- GitHub Actions 已由首次主分支推送真实触发；它发现本机环境掩盖的 DOCX/PDF 锁依赖遗漏，并推动增加依赖一致性契约测试。
- 没有连接生产服务器，也没有执行数据库备份或恢复。

## 一句话面试表达

我把后端、前端、浏览器验收、真实 PostgreSQL 集成测试和确定性 RAG 指标做成了可复用质量门禁；版本
发布在门禁通过后生成带供应链证据的不可变镜像，生产部署仍通过备份、独立迁移、人工批准、冒烟和
回滚清单控制风险。
