# 第 7 步知识点总结：分块与向量写入

## 你现在应该能讲清楚的主线

解析后的整篇文档不适合直接检索。系统先按段落、换行和中英文标点切成有重叠的片段，保存每个片段在全文中的位置和内容指纹，再通过向量 Provider 生成固定1024维表示，最后在一个事务中写入 PostgreSQL 的 `vector(1024)` 列。正式环境使用 `qwen3.7-text-embedding`，测试环境使用不联网的确定性替身。任务状态记录解析、分块、向量化和写入阶段，重复执行会替换同一版本的片段并保持稳定编号。

## 十个核心知识点

1. 分块大小影响上下文完整性、检索精度、成本和延迟，不能凭感觉宣称最优。
2. 相邻重叠降低答案跨边界丢失的风险，也会增加存储和向量生成量。
3. 起止位置让片段能回到原文，支撑可核对引用。
4. 向量维度由模型决定，数据库固定维度可以提前拒绝错误数据。
5. Provider 抽象隔离业务规则和模型供应商。
6. 离线确定性向量适合工程测试，但不能冒充生产语义模型。
7. pgvector 没有近似索引也能执行精确距离查询，适合先建立质量基线。
8. 片段和任务状态必须原子提交，避免任务显示成功但向量缺失。
9. 稳定编号和数据库唯一约束共同保证重复任务幂等。
10. 历史数据需要显式回填，数据库迁移不能只考虑新记录。
