# 第 12 步知识点总结：企业级运行时加固

## 完成的工程能力

- 为认证、回答生成和普通业务接口建立不同强度的固定窗口限流。
- 超限返回 `429`、`Retry-After`、限制总数和剩余次数。
- 使用访问令牌或网络地址的 SHA-256 摘要区分客户端，不保存原始凭证。
- 为向量生成增加有界、可过期、最近最少使用淘汰和并发填充保护的内存缓存。
- 把关键身份、知识库、成员、文档和任务操作写入 PostgreSQL 审计表。
- 提供仅管理员可用的审计过滤查询与全局摄取任务队列查询。
- 通过 Prometheus 标准格式暴露请求、限流、缓存、检索、模型和任务指标。
- 使用固定路由模板和有限标签，避免高基数和敏感数据进入指标。
- 为接口响应增加来源策略、浏览器能力策略和内容安全策略。
- 记录 ADR-0006，明确本地实现和多实例生产替换条件。

## 最重要的设计判断

- 缓存的是文本向量，不是权限相关的检索结果和回答。
- 限流和缓存位于单个进程，两个以上实例必须迁移到共享存储。
- 审计只保存必要元数据，不读取密码、令牌、问题正文和文档内容。
- 指标只使用受控标签，不使用用户编号、知识库编号、文件名或完整路径。
- 指标令牌与用户登录令牌分离，生产环境还必须限制网络可达范围。
- 追加式审计不等同于绝对防篡改，数据库高权限仍需单独治理。

## 当前默认配置

| 项目 | 默认值 |
|---|---:|
| 限流窗口 | 60 秒 |
| 注册与登录 | 每窗口 10 次 |
| 回答生成 | 每窗口 20 次 |
| 其他业务接口 | 每窗口 120 次 |
| 向量缓存容量 | 512 项 |
| 向量缓存生存时间 | 300 秒 |

这些值是安全的本地起点，不是生产容量结论。
