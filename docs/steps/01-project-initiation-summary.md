# 第 1 步总结：项目立项

## 本步完成了什么

- 明确项目要解决的企业知识检索问题。
- 确定系统管理员、知识库所有者、编辑者和查看者四类角色。
- 列出第一版必须实现和明确暂不实现的功能。
- 制定分阶段学习与开发路线。
- 建立项目术语表。
- 建立本地 Git 版本库，主分支名为 `main`。
- 完成首次环境盘点。

## 当前环境盘点

| 工具 | 当前结果 | 用途 | 后续动作 |
|---|---|---|---|
| Git | 已安装，版本 2.53.0 | 保存代码历史和支持团队协作 | 第 2 步学习分支、提交和合并 |
| Node.js | 已安装，版本 20.17.0 | 运行前端开发工具 | 第 2 步判断是否需要升级 |
| npm | 已安装，版本 10.8.2 | 安装和管理前端依赖 | 第 2 步验证依赖管理方式 |
| Python | 当前命令环境找不到 | 运行后端服务、任务和测试 | 第 2 步定位或安装稳定版本 |
| Docker | 当前命令环境找不到 | 用容器运行数据库、缓存和应用 | 第 2 步定位或安装 Docker Desktop |

“当前命令环境找不到”不一定代表电脑上完全没有安装，也可能是可执行文件没有加入环境变量。第 2 步会先查明原因，再决定是否安装。

## 必须掌握的知识点

1. 检索增强生成不是重新训练大语言模型，而是在回答时动态补充外部证据。
2. 企业级系统不仅看功能，还看权限、安全、稳定、审计、测试、部署和效果证据。
3. 项目章程先明确目标、用户、范围和完成标准，避免开发过程中失去方向。
4. 第一版要优先形成端到端闭环，并明确排除项以控制范围。
5. 模块化单体适合小团队起步；微服务应该由真实的独立扩展或组织需求驱动。
6. 评测指标必须来自可复现实验，不能把少量演示结果包装成正式结论。

## 自我检查

如果你能不用看文档回答下面三个问题，就可以进入下一步：

1. 这个系统给谁用，解决什么问题？
2. 一次完整问答从上传文档到返回引用经历哪些阶段？
3. 为什么当前先用模块化单体，而不是微服务？
