# 第 9 步知识点总结：DeepSeek 带引用问答

## 你现在应该能讲清楚的主线

用户只能向自己有权访问的知识库提问。系统复用混合检索取得最新成功文档版本的片段，把片段编号为 `[S1]`、`[S2]` 后发送给 DeepSeek。系统提示词把来源声明为不可信数据，并要求资料不足时拒答。模型返回后，应用验证所有引用编号都来自本次候选；不合法就失败关闭为固定拒答。最终回答、模型用量和引用快照写入 PostgreSQL，再返回普通 JSON 或校验后的服务器发送事件。

## 十二个核心知识点

1. 业务服务依赖小型生成 Provider，避免绑定 DeepSeek 的具体调用代码。
2. DeepSeek 使用 Bearer 密钥调用聊天补全接口，真实密钥只在被 Git 忽略的本地文件中。
3. 系统提示词保存稳定规则，用户提示词携带本次问题和授权证据。
4. 文档内容是不可信数据，不能因为进入模型上下文就当成系统命令。
5. Grounding 是让回答基于可检查证据，不等于保证绝对正确。
6. 固定拒答使客户端和评测程序可以稳定识别证据不足结果。
7. 引用白名单防止模型编造不存在的 `[S99]`，失败时采用保守拒答。
8. 引用存在性校验不能证明来源真正支持结论，仍需答案忠实度评测。
9. 上下文预算控制模型输入成本和噪声，当前按字符数实现第一版。
10. 引用快照保留生成时证据，支撑历史审计，但也增加敏感数据治理责任。
11. 校验后流式输出优先保护引用完整性，代价是首个事件等待完整生成。
12. 外部模型错误必须转为稳定公共错误，不能回显密钥或供应商敏感正文。

## 本步真实证据

- 默认真实生成模型：`deepseek-v4-flash`。
- 真实冒烟结果：`OK`，输入 94 个词元，输出 15 个词元。
- 数据库迁移：`20260828_0005`。
- 新表：`grounded_answers`、`answer_citations`。
- 普通接口：`POST /api/v1/knowledge-bases/{id}/answers`。
- 流式接口：`POST /api/v1/knowledge-bases/{id}/answers/stream`。
- 自动化用例覆盖生成故障、引用、拒答、快照、权限隔离和流式事件。
- 自动化测试：72 个全部通过；分支覆盖率 84.03%，门槛为 80%。
- 测试库迁移回退和重新升级、开发库与测试库漂移检查通过。
- Ruff 代码规范和 Mypy 严格类型检查通过。
