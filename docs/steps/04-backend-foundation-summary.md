# 第 4 步完成总结：后端最小骨架

## 完成了什么

1. 使用 FastAPI 和 Uvicorn 建立可真实启动的后端应用。
2. 用应用工厂统一组装配置、日志、中间件、错误处理和路由。
3. 建立按环境变量加载并校验的配置体系。
4. 实现请求编号、安全响应头、请求耗时和 JSON 结构化日志。
5. 实现统一错误模型，避免未知异常泄露内部信息。
6. 实现职责不同的存活与就绪检查。
7. 建立直接依赖清单、完整依赖锁文件和开发依赖隔离。
8. 建立 Pytest、覆盖率、Ruff 和 Mypy 质量门禁。

## 你应该掌握的知识点

- FastAPI 负责定义接口和数据校验，Uvicorn 负责监听网络并运行应用。
- 应用工厂让生产和测试共用组装过程，又允许测试注入不同配置。
- 环境变量把会随部署环境变化的值移出代码，敏感值不能写进版本库。
- 中间件适合处理所有请求共享的横切能力，例如请求编号、日志和响应头。
- 请求编号将一次请求的客户端反馈、访问日志和错误日志关联起来。
- 结构化日志的字段比自由文本更适合机器查询、统计和告警。
- 存活检查回答“进程要不要重启”，就绪检查回答“现在能不能接流量”。
- 统一错误码给前端稳定契约，未知异常的技术细节只保留在服务端日志。
- 锁文件降低不同环境安装出不同依赖版本的概率。
- 测试覆盖率只是辅助指标，不能替代有意义的成功、边界和失败场景测试。

## 自己复习时的操作

1. 阅读 [`docs/04-backend-foundation.md`](../04-backend-foundation.md)。
2. 打开 `backend/app/main.py`，从应用工厂追踪到路由、中间件和错误处理。
3. 运行 `scripts/verify-backend.ps1`，观察四类自动检查。
4. 启动服务并访问 `/docs`、`/live`、`/ready`。
5. 带一个自定义 `X-Request-ID` 发请求，然后在日志中找到相同编号。
