# 第 6 步知识点总结：文档摄取

## 你现在应该能讲清楚的主线

文档上传不是“把文件复制到目录”这么简单。企业系统必须先做服务端权限检查，再流式限制大小，同时核对扩展名、媒体类型和文件结构。原文件用系统生成的对象键不可变保存，数据库记录逻辑文档、版本、SHA-256 指纹和后台任务。独立工作进程领取任务、提取文本并更新状态，失败按照永久或暂时类型决定是否有限重试。

## 十个核心知识点

1. 文件名和媒体类型都来自客户端，不能单独信任。
2. 流式读取能在超过上限时尽早停止，避免一次把大文件全部放进内存。
3. 服务器生成存储键能够防止路径穿越，也避免 Windows 路径过长。
4. 不可变版本保证历史引用、审计和回滚依据可靠。
5. SHA-256 是完整性指纹，不是加密，也不是密码哈希方案。
6. 上传请求和耗时解析分离，用户可以得到可追踪任务编号。
7. PostgreSQL 的行锁和 `SKIP LOCKED` 可以支持多个队列消费者并发领取。
8. 消息可能重复交付，后台任务必须幂等。
9. 永久错误不应无限重试；暂时错误使用次数上限和指数退避。
10. 工作进程可能崩溃，所以任务需要锁定时间和陈旧任务恢复规则。
