# 第 5 步完成总结：数据库与身份权限

## 完成了什么

1. 连接本机 PostgreSQL 17.11，并建立 `rag1` 与 `rag1_test` 隔离环境。
2. 创建非超级管理员的正式和测试应用账户。
3. 使用 SQLAlchemy 异步会话与 Psycopg 3 访问数据库。
4. 使用 Alembic 创建可升级、可回退、可检查漂移的第一版结构。
5. 实现用户注册、登录、当前用户和管理员引导。
6. 使用 Argon2 保存密码哈希，使用 30 分钟签名访问令牌。
7. 实现 `admin/member` 全局角色和 `owner/editor/viewer` 资源权限。
8. 实现知识库创建、权限过滤和成员授权。
9. 为 Windows 增加兼容异步 Psycopg 的统一服务启动入口。

## 必须掌握的知识点

- 超级管理员只做数据库管理，应用使用最小权限账户。
- 正式数据库与自动化测试数据库必须隔离，并由代码验证目标。
- SQLAlchemy 是数据访问层，Psycopg 是 PostgreSQL 驱动，Alembic 管理结构版本。
- 迁移文件是数据库结构的历史，模型和实际数据库不能漂移。
- 密码哈希是单向验证，不是可逆加密；盐值能让相同密码得到不同哈希。
- JSON 网络令牌有签名但没有加密，令牌内容不能放秘密。
- 身份认证回答“你是谁”，权限授权回答“你能做什么”。
- 全局角色与资源角色解决不同范围的权限问题。
- 权限过滤应尽量进入数据库查询，不能先把全部数据读出再过滤。
- 无权访问私有资源时返回 404，可以降低资源编号探测风险。

## 复习顺序

1. 阅读 [`docs/05-database-and-authorization.md`](../05-database-and-authorization.md)。

5. 从 `knowledge_bases/router.py` 追踪到资源权限查询。

## 安全待办

- 本机 `postgres` 超级管理员密码过于简单，应单独更换。
- 生产环境需要加密连接、密钥管理、登录限速、多因素认证和令牌撤销策略。
- 测试客户端有一条第三方弃用警告，后续依赖升级时处理。
