# 发布与回滚检查清单

## 发布前

- [ ] 需求、验收条件、架构决策和数据库迁移已经审查。
- [ ] 后端、前端、浏览器流程、确定性 RAG 质量门禁和镜像构建全部通过。
- [ ] 没有真实密钥、`.env`、企业文档或备份进入 Git。
- [ ] 依赖锁文件与本次安装一致。
- [ ] 已记录当前运行镜像版本与摘要。
- [ ] 已创建数据库和对象文件备份，并验证校验值。
- [ ] 最近一次恢复演练在恢复时间目标以内。
- [ ] 已确认发布负责人、批准人、时间窗口和回滚负责人。
- [ ] 新配置已在预发布环境验证，密钥不是模板值。
- [ ] 数据库迁移已人工阅读，并确认旧版本兼容策略。

## 发布中

- [ ] 一次只允许一个生产发布运行。
- [ ] 先运行数据库迁移，再启动依赖新结构的应用。
- [ ] 持续观察迁移、后端、工作进程、前端和数据库日志。
- [ ] 不在服务器现场修改源码或镜像内容。
- [ ] 记录开始时间、标签、提交编号、镜像摘要和执行人。

## 发布后

- [ ] 前端 `/healthz` 正常。
- [ ] 后端存活和就绪检查正常。
- [ ] 登录、上传、任务处理、检索、问答和引用冒烟通过。
- [ ] 管理员能查看审计事件和摄取任务。
- [ ] 错误率、延迟、模型失败和任务积压没有异常上升。
- [ ] 发布记录包含验证结果和遗留问题。

## 回滚触发条件

- [ ] 存活或就绪检查持续失败。
- [ ] 登录、权限或核心问答链路不可用。
- [ ] 出现数据泄露、权限绕过或密钥暴露。
- [ ] 错误率、延迟、费用或任务积压越过事先确定的阈值。
- [ ] 数据库迁移失败或出现不可接受的数据不一致。

## 回滚后

- [ ] 恢复到明确记录的上一镜像版本或摘要。
- [ ] 没有未经评审地执行破坏性数据库降级。
- [ ] 重新执行全部健康检查和核心冒烟。
- [ ] 保存证据并建立事故时间线。
- [ ] 创建根因分析与后续改进任务。
