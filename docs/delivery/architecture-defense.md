# 架构答辩手册

## 1. 总体答题框架

每个架构问题按四句话回答：选择了什么；为什么适合当前约束；付出了什么代价；什么条件出现时演进。

## 2. 为什么采用模块化单体，而不是微服务？

选择：一个可部署后端中保持认证、知识库、摄取、检索、问答、审计等清晰模块，后台工作进程复用同一套
应用代码。原因：当前是单人项目和单机部署，模块化单体能保留边界又减少服务发现、分布式事务和观测成本。
代价：模块无法单独部署或扩缩。演进：当某个模块出现独立团队、不同发布节奏或可测量的独立扩容需求时，
再通过现有接口与任务边界拆分。

## 3. 为什么使用 PostgreSQL 与 pgvector？

选择：关系数据、权限、任务、全文索引和向量都放在 PostgreSQL。原因：可以利用事务、约束和成熟运维，
一次查询完成资源权限过滤，避免两个存储之间同步。代价：超大规模向量检索和专用算法选择少于独立向量
数据库。演进：先用真实数据测量容量和延迟，当索引规模或吞吐成为瓶颈，再迁移向量提供者实现。

## 4. 为什么做混合检索？

关键词检索擅长编号、产品名和精确术语，向量检索擅长同义表达。两者并行召回后使用倒数排名融合，只依赖
排名而不直接比较不同分数尺度。代价是多一次查询并需要调节候选数；评测集用于防止融合后质量退化。

## 5. 为什么使用倒数排名融合？

全文相关度和向量距离不在同一个数值空间，直接加权需要归一化和大量调参。倒数排名融合按名次贡献分数，
实现稳定、易解释。它不会学习复杂排序关系；数据量和标注充分时可增加重排模型并与当前基准线对比。

## 6. 为什么文档处理异步化？

PDF 或 DOCX 解析、分块和向量写入耗时且可能失败。上传接口只保存版本和任务，工作进程领取持久任务，
可以重试并恢复陈旧任务。当前 PostgreSQL 队列表简单且事务一致；高吞吐、多机消费者或复杂调度出现时，
可以引入 Redis 与 Celery，但同时要承担新基础设施和消息一致性成本。

## 7. 为什么文档版本不可变？

问答引用需要指向当时实际使用的内容。更新文档时创建新版本，旧引用仍可追溯，也便于审计和重建索引。
代价是占用更多存储，需要制定保留与归档策略。

## 8. 权限如何防止越权检索？

系统同时有全局角色和知识库资源角色。查询在数据库检索阶段就带知识库和成员条件，只让获授权片段进入
排序和模型上下文。不能先全库检索再在页面隐藏，因为原文可能已经泄露给模型、日志或缓存。

## 9. 如何降低模型幻觉？

只提供检索上下文；提示模型资料不足时拒答；每个来源使用服务端分配的标识；解析回答后校验引用必须来自
当前上下文；评测引用准确率、召回率与拒答行为。它只能降低风险，不能数学上保证模型永不出错，因此界面
仍需显示原文并让用户核对。

## 10. 为什么抽象模型提供者？

业务层依赖统一生成接口而不是 DeepSeek 的具体请求格式，测试可以使用确定性实现，也便于更换供应商。
抽象不能自动消除不同模型的上下文长度、流式协议和能力差异，这些差异仍需适配测试。

## 11. 为什么常规门禁不用真实 DeepSeek？

外部调用会产生费用、随机性、限流和数据外发风险。每次提交运行确定性完整链路，真实模型只在资料获授权、
预算明确的发布前实验中运行，并单独保存提供者与模型版本。确定性通过不代表真实模型一定通过。

## 12. 为什么缓存和限流目前只适合单进程？

当前计数和缓存保存在进程内存，开发简单且无额外依赖；多个应用实例会各自维护状态，导致总限额不一致、
缓存重复和失效不同步。进入多实例前应使用 Redis 等共享实现，并设计键空间、过期和故障降级。

## 13. 为什么要审计日志，而普通日志不够？

普通日志主要帮助诊断，可能轮转且内容不稳定。审计事件使用结构化字段记录主体、动作、资源和结果，并在
数据库中追加保存，支持安全追责。当前追加式应用接口不等于不可篡改，生产还应限制数据库权限并外送保存。

## 14. 为什么迁移独立于应用启动？

多个副本同时迁移会竞争，迁移失败后继续启动会造成代码与结构不一致。部署先运行一次迁移，成功后才启动
接口和工作进程。数据库变更优先采用扩展与收缩，应用回滚时不默认执行破坏性降级。

## 15. 为什么采用持续交付而不是持续部署？

门禁通过后自动生成可部署镜像，但生产上线保留人工批准。企业文档、数据库迁移和外部模型费用都需要明确
变更窗口与责任人。以后即使自动化更完整，是否取消批准也应由风险等级决定，而不是追求自动化数量。

## 16. 系统目前最大的三个风险

1. 评测语料太小，不能代表复杂表格、扫描件、跨文档冲突和真实领域语言。
2. 单机数据库、进程内缓存和限流不具备多实例高可用能力。
3. 容器与流水线尚未在真实远程环境运行，静态测试不能覆盖网络、磁盘、证书和权限配置问题。

下一步应先扩大经过脱敏和人工标注的评测集，再在隔离环境运行流水线、容器、备份恢复和故障演练，最后
根据测得的容量数据决定是否引入 Redis、对象存储或独立向量数据库。
