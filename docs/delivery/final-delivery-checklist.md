# 最终交付检查清单

## 面试前一天

- [ ] PostgreSQL 17 正常运行，测试知识库可重新创建。
- [ ] 执行 `scripts/verify-interview-delivery.ps1` 并确认全部通过。
- [ ] 用虚构样本文档完整排练两次，第二次控制在 15 分钟内。
- [ ] 确认 `.env`、`.env.deepseek`、部署真实密钥和备份目录未被 Git 跟踪。
- [ ] 不升级依赖，不安装 Docker，不修改数据库版本。
- [ ] 保存确定性报告和 DeepSeek 实验报告的本地只读副本。
- [ ] 关闭会弹出密钥、个人通知或无关代码的窗口。
- [ ] 准备无需网络的架构、测试和评测材料。

## 面试开始前 30 分钟

- [ ] 依次启动 PostgreSQL、后端、工作进程和前端。
- [ ] 打开就绪检查和前端工作台，完成一次测试登录。
- [ ] 清理演示知识库中的旧数据，保留一个确定的演示路径。
- [ ] 检查屏幕缩放、字体和网络，不在屏幕上显示环境变量。
- [ ] 给 DeepSeek 现场调用设置一次尝试上限，失败后立即降级。

## 演示过程中

- [ ] 先讲业务问题，再展示页面。
- [ ] 展示一次有依据回答和一次资料不足拒答。
- [ ] 主动说明指标的 3 份文档、5 个问题边界。
- [ ] 主动说明 Docker 与 GitHub Actions 尚未真实运行的边界。
- [ ] 遇到故障先说明事实，再切换保存证据，不假装现场成功。

## 提交或公开仓库前

- [ ] `git status` 中没有本地环境文件、数据库备份、日志或依赖目录。
- [ ] 运行秘密扫描且不在输出中打印秘密值。
- [ ] 检查 README 的启动说明、当前阶段和限制仍然准确。
- [ ] 检查所有 Markdown 本地链接。
- [ ] 如果推送 GitHub，观察首次 Actions 运行并修正真实环境差异。
- [ ] 在流水线成功前不添加“构建通过”徽章。
- [ ] 不公开任何未经授权的公司资料或真实评测问题。

## 面试后复盘

- [ ] 记录被追问但回答不清楚的问题。
- [ ] 区分知识缺口、表达缺口和项目真实缺口。
- [ ] 只在补充实现并重新验证后更新简历结论。
